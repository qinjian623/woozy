# 语义与运行时实施约定

版本：`compiler-dev/1`。本文件补充词法语法 v0.1 尚未固定的行为，属于本轮实施默认值。除明确列出的阶段限制外，不得由不同后端自行选择不同语义。

## 1 与语法规范的关系

[LEXICAL_SYNTAX.md](../baseline/LEXICAL_SYNTAX.md) 规定表层语法；本文件规定值、求值、错误和资源行为。现有 EBNF 与原型不因此成为完整语义检查器。下面明确标为未支持的表达会被解析，但检查阶段必须报告 `E_CAPABILITY_UNAVAILABLE`。

当前不扩充 `?`、`null`、指针运算符、`class`、默认参数或宏。`auto` 推断通过 `let/var` 省略类型表达。

## 2 名称与模块

- 普通名字采用一个词法命名空间，绑定带 kind；先选择最近绑定，再检查是否为所需种类。类型位置不会绕过同名局部变量去寻找外层类型。
- 同一作用域重名报错；嵌套局部作用域允许遮蔽，诊断可附可选提醒。预定义名称在最低优先级 prelude；`Self` 仅在 trait/impl 上下文有效。
- import alias 只在当前文件有效；同包顶层声明在包内共享；`pub` 导出，不允许公开接口泄漏不可访问的私有类型。
- 包依赖必须为 DAG；循环导入在解析依赖图时报告完整循环路径。函数之间的递归允许，与包循环不同。
- 第一版顶层只实施 `const`、类型、函数、trait/impl。顶层 `let/var` 即使可解析，也报告未支持；不引入隐式动态模块初始化。
- 同一包的所有源文件必须声明一致的 package 名。导入路径以项目清单映射为准，磁盘枚举顺序不能改变含义。

源作用域固定如下，Python 的函数级局部变量规则不能覆盖它们：

| 构造 | 名称作用域 |
| --- | --- |
| 函数参数与最外层函数体 | 同一局部作用域，函数体不能直接重声明同名参数 |
| 普通 `{}`、if/else 分支 | 各自建立子作用域 |
| 局部 let/var/const 绑定 | 类型标注与初始化表达式在声明前的环境中解析；初始化完成后，新绑定才可见。内层 `let x = x + 1` 使用外层 x；不存在外层 x 时报告未声明名称 |
| 三段式 for 的初始化绑定 | 位于循环作用域，对条件、步进和循环体可见，循环后不可见 |
| 循环体 | 每轮进入新的子作用域；本轮 defer 不保留到下一轮 |
| for-in 的元素绑定 | 每轮建立，在本轮循环体作用域内有效；集合表达式在外部求值一次 |
| switch 的 case/default | 每个分支建立隐式词法作用域，模式绑定只在本分支有效 |
| catch 的错误绑定 | 与对应 catch 体同一作用域，不进入其他 catch 或 try 后方 |


## 3 基础类型与推断

实现 `bool`、`i8/i16/i32/i64`、`u8/u16/u32/u64`、`isize/usize`、`f32/f64`、`string`、`Unit`。`isize/usize` 宽度来自目标描述；Python profile 初期按其声明的目标字宽工作，禁止直接按运行 Python 的宿主宽度推断。

整数和浮点字面量先保留未定类型常量。有上下文时检查目标类型，无上下文时默认 i64/f64。负整数字面量在完成一元负号语义后检查范围，允许最小负整数；不能在 lexer 中先把正数字面量塞进宿主 i64。

变量之间不隐式混合有符号、无符号、不同位宽或整数与浮点；字面量可以受上下文约束。赋值、实参、返回值均使用这一规则。显式转换使用 `T(x)`。整数到整数转换做范围检查；浮点到整数先向零截断，再按截断后的数学整数检查目标范围，NaN、无穷或越界产生 Panic。整数到浮点按目标精度采用 round-to-nearest ties-to-even。编译期能确定转换失败时直接报源码错误，只有动态失败才产生 Panic。这里规定转换行为，具体已支持的组合仍以两后端实现记录为准。

函数接口必须显式声明参数和返回类型；省略返回类型是 Unit。局部推断不跨模块反推公开接口，不通过运行表达式来推断类型。空列表需上下文提供元素类型。

列表的共同元素类型不依赖元素书写顺序。有 Vec 上下文时使用其元素类型；没有上下文时，具体元素类型约束同类的未定类型字面量，例如 `[1, x]` 与 `[x, 1]` 在 x 为 i32 时都得到 Vec[i32]。嵌套列表和空列表也可从同一列表中的其他元素取得类型，例如 `[[], [x]]` 得到 Vec[Vec[i32]]；全部为空且没有其他类型信息时仍须外部上下文。没有其他约束时仍使用上述 i64/f64 默认类型。具体类型不兼容时报错，不增加整数与浮点之间的隐式转换。类型检查可以先取得后方元素的类型，运行时仍按源码顺序求值。

const 允许纯 struct/enum 的递归常量构造，以及常量字段读取；组成值必须同样可在编译期确定。Vec、外部对象和普通函数的编译期执行不在此范围内。已有标量、string 和非捕获函数值常量继续适用；只读、名称作用域、可见性和常量环检查不因聚合常量改变。

## 4 数值运行语义

### 4.1 整数

| 运算 | 行为 |
| --- | --- |
| `+ - *` 与一元 `-` | 固定位宽模运算；结果按目标有符号/无符号类型解释 |
| 有符号 `/` | 向零截断；`MIN / -1` 返回 MIN，必须在 LLVM `sdiv` 前特判 |
| 有符号 `%` | 余数符号随被除数；`MIN % -1` 返回 0 |
| 无符号 `/ %` | 普通无符号商和余数 |
| 除数为 0 | Panic，不能由 typed catch 捕获 |
| `<<` | 舍弃移出位，结果保持位宽；移位量必须在 `[0,width)` |
| 有符号 `>>` | 算术右移；无符号为逻辑右移 |
| 移位量为负或不小于位宽 | Panic；不能把非法移位直接交给 LLVM |
| 比较 | 按已经确定的有符号性选择指令 |

移位左操作数必须为整数，右操作数允许任意整数类型，但先在其数学取值上检查有效范围。bitwise 运算其他两操作数要求同一具体整数类型。

字面量超出目标类型范围与已定类型表达式运算回绕不同：`let x i8 = 128;` 是静态错误；`let x i8 = 127; let y = x + 1;` 得到 -128。常量折叠必须复用同一套数值规则。

### 4.2 浮点

基本运算按 f32/f64 的 IEEE 754、round-to-nearest ties-to-even 处理，保留 NaN、无穷与带符号零；默认禁用 fast-math，不隐式融合乘加。源语言 `%` 初期只接受整数。

Python 的 f32 标量运算需显式舍入；浮点除零、NaN 和无穷不能直接继承 Python 异常行为。f32/f64 的运行时适配必须有独立预期值测试，在实现前对应能力维持未支持。仅外部 ndarray/Tensor 的 dtype 操作由外部库执行，不等同于已实现全部本语言 f32 标量语义。

不保证不同平台 libm、外部库或浮点归约逐位一致。浮点测试分别验证分类、符号零和明确容差；不能仅用一个宽松容差掩盖整数或清理错误。

不承诺 NaN payload 位模式或浮点异常标志。声称支持严格标量浮点的目标须满足约定舍入模式与 subnormal 行为；改变浮点环境的外部调用在支持前拒绝或隔离。十进制字面量应在确定目标精度后直接正确舍入，不能全部先解析成宿主 double 再转 f32。Python f32 适配还要验证溢出、subnormal 与边界值，不能仅用“f64 运算后 pack”就认定全部正确；无法保证的操作继续报告未支持。

显式 f64→f32 转换采用 IEEE round-to-nearest ties-to-even；溢出得到带符号的 Inf，保留正负零与 NaN，但不承诺 NaN payload。常量与动态转换使用相同规则；这类浮点窄化溢出不产生编译错误或 Panic。f32→f64 扩大转换保持原值。

## 5 求值与控制流

- 操作数、被调用者、实参按源码从左到右求值；`&&`、`||` 短路。
- 命名实参先按书写顺序求值到临时值，再按签名排列。重排参数不能重排副作用。
- 赋值目标的地址/索引先求值一次，再求右值；复合赋值不能重复计算下标或接收者。
- `if/for` 条件必须是 bool。赋值不是表达式，没有隐式真假转换。
- struct 字段按声明顺序布局的逻辑顺序记录；构造实参仍按源码顺序求值。底层 ABI 布局由目标降低单独决定，不承诺与 C++ 相同。
- `return expr` 先求值并保存拥有的返回结果，再执行退出路径的清理。返回值不能借用即将释放的局部存储。
- 非 Unit 函数所有可达正常结束路径必须返回；无限循环和无正常返回的 Panic 可作为终结路径。
- `switch` 无 fallthrough，分支按源码顺序匹配。覆盖按实际值域判定：没有 default 时，只要已证明所有值都被覆盖即可接受；否则报源码错误。枚举必须覆盖全部变体（真正空枚举按既有规则无值可覆盖），bool 必须同时列出 true/false，确实列全的有限整数域可省略 default；float、string 和未列全的整数常量不能单独证明穷尽。任何合法类型都可以用 `_`、裸标识符或显式 default 作总匹配，Vec、POD、函数值和 Unit 不因此获得新的相等运算。
- 裸标识符模式始终引入新绑定，即使外层存在同名 `const` 也不作常量匹配；`case NaN:` 是名为 NaN 的绑定而不是浮点常量，不新增 NaN token。`_` 不产生可读绑定，绑定只在对应分支作用域有效。
- 字面量模式按其目标类型的值相等匹配，不引入 switch 专用的隐式转换。整数先按实际类型检查范围并比较数学值，`16` 与 `0x10` 相同；bool 只有 true/false，不能与整数 1/0 混用。float 使用 IEEE `==`：正负零相等，正确舍入后相同的不同拼写相等，NaN 不匹配任何字面量而只能落到总匹配分支。string 比较 lexer 解码后的完整 UTF-8 字节，包含嵌入 NUL、原始多行内容和不同转义得到的同内容；不做 Unicode 归一化、不按地址或 C 零终止串比较，普通源语言字符串比较采用同样的值规则。
- `switch` 的主体表达式只求值一次。计算得到的拥有值持有到所选分支执行结束：先完成该分支实际注册的 defer、模式绑定和局部清理，再按正常退出、return、throw、break 或 continue 的既有退出计划释放主体，之后才进入外层作用域清理。匹配失败的 arm 不建立绑定、不复制拥有载荷；typed throw 按其 handler 退出，Panic 仍不承诺语言清理。分支仍拥有的载荷绑定按既有复制与清理规则处理。

表达式语句、绑定初始化、赋值和每次条件求值分别形成 full-expression。未转移出去的拥有临时值在该 full-expression 结束时按创建逆序销毁，条件临时值在进入分支/循环体前清理。return/throw 的结果先转移到专用输出拥有槽，其余临时值先清理，再执行退出词法块的 defer 和局部销毁。

调用实参求值中发生 typed error 时，已创建临时值按逆序清理，未求值的实参不执行。`move x` 在其表达式求值时就把所有权从 x 转移到临时值；若后续实参失败，由调用前清理销毁该临时值，不能把 x 悄悄恢复为可读。真正进入被调用函数后，move 参数由被调用方负责销毁或转移。

## 6 泛型和 trait

泛型设计以 Go、Java 一类常规类型参数和约束为目标，不追求 C++ 模板元编程。保留泛型函数、类型、方法及 trait 约束；不引入非类型模板参数、变参模板、模板特化或部分特化，也不通过替换失败筛选候选声明（SFINAE）。单态化是生成代码的实现选择，不扩大源码可用的泛型规则。

使用现有 `[T]` 与 `[T Trait]` 语法。第一版采用名义 trait 和显式 impl，方法签名必须匹配。一个实现由真实 trait 声明、有序类型实参和 Self 共同确定；每个完整组合最多一个有效实现。相同 Self 可以实现同一 trait 的不同实参组合；实现重叠时仍报错。直接方法调用无法确定唯一实现时报告歧义，不根据预期返回类型猜选；受约束的 T 调用按完整 trait 实参选择。

`dyn Trait` 和 `dyn Trait[Args]` 是显式 trait object 类型。具体值在具有唯一完整 trait 实现时可以转换为对应的 dyn 类型；转换按普通值规则复制拥有数据，`move` 则先转移再装箱。dyn 方法按 trait 声明顺序进入 vtable，调用时使用对象内的具体实现。trait object 的复制共享同一个装箱值，最后一次销毁释放装箱值和其中的拥有字段；`Vec[dyn Trait]` 的元素复制/销毁使用同一规则。`Convert[i32]` 与 `Convert[bool]` 是不同的 dyn 类型，不共享 vtable 或实现选择。

作为 dyn 使用的 trait 必须对象安全：每个方法有普通 `self Self` 接收者，所有非接收者参数必须是 ordinary；`move` 或 `inout` 参数（包括 `move i32`）同样对象不安全。方法不能声明自身的泛型参数，不能抛出 typed error，不能返回 `Self`，也不能在非接收者参数中使用 `Self`；这些限制在声明 dyn 类型或构造对象时以 `E_OBJECT_UNSAFE` 报告。重叠或歧义实现仍在声明阶段拒绝。暂不支持把 dyn 方法当函数值、dyn 的泛型方法或 dyn 作为 impl 目标；也不支持特化、关联类型和重叠 impl。

泛型函数体依据声明约束检查，调用时解析实参、满足约束，并对实际使用的具体组合单态化。不同包的实例化使用规范化类型键去重；无限递归实例化和超预算产生诊断，不让编译器耗尽资源。

方法的类型名调用与值调用使用相同的声明参数。`value.method(args)` 按已有接收者规则传入 value；`Type.method(...)` 和受对应 trait 约束的 `T.method(...)` 不自动补接收者，调用者显式提供全部声明参数，包括普通首参 Self。无接收者的工厂函数同样按声明传参，零参数函数允许空实参表。T 只用于确定方法所属类型、检查声明约束和选择 impl，不产生运行时的 T 值，也不根据实参或预期返回类型猜测另一项 trait。

同一目标方法确定后，两种调用形式保留相同的参数模式、复制/借用、求值顺序和错误传播规则。值调用是否省略首参由已有接收者规则决定，不因泛型替换后首参类型碰巧等于 Self 而改变。以上调用规则已于 2026-11-05 确认；各参数模式的实际支持范围仍见 [GENERICS.md](../development/docs/GENERICS.md)，不据此自动开放尚未实现的 move/inout Self。

首位真实 Self 参数采用 move 或 inout 时，接收者写作 `(move x).take()` 或 `(inout x).change()`。普通 `x.method()` 不自动移动 x，也不自动取得可写访问；Type/T 方法调用仍显式提供全部声明参数。首参名可以是 self 或 owner，接收者身份取决于声明中的 Self，不能由具体化后碰巧相同的类型推定。已有整体移动、inout 类型与别名限制继续适用，不增加字段部分移动或非平凡拥有值 inout。

每个已实施类型都有明确的复制与销毁行为。第一版不引入用户定义 move-only 类型；泛型读取或返回参数按其类型执行逻辑 copy，托管引用为 retain，值结构按字段递归复制。

## 7 值、容器与 ARC

### 7.1 复制与对象身份

| 类型 | 逻辑复制 |
| --- | --- |
| 数值、bool、Unit | 复制值 |
| 函数值 | 复制函数与捕获环境；共享环境增加引用，最后一次清理释放 |
| struct/enum | 按字段或活动变体递归 copy；活动字段仅销毁一次 |
| string | 不可变 UTF-8 值；底层可共享存储，用户观察不到可变别名 |
| Vec[T] | 共享同一个容器对象，新增拥有句柄；无隐式深复制或 COW |
| Python ndarray/Tensor 等外部引用 | 保留原对象身份；所有权由绑定和 Python runtime 维护 |
| py.Error | 共享同一 Error 载荷及原 Python Exception、cause、traceback 对象；语言清理只释放该拥有槽 |

`let` 禁止重新绑定和修改本语言值字段；引用对象允许通过已声明的可变操作修改内部状态。Vec 的索引赋值修改共享容器，所有别名可观察到；这一点在 native 与 Python runtime 中必须相同。

原生 Vec 索引为非负整数，越界 Panic。切片 `[start:end]` 返回新的 Vec，复制元素的逻辑值，区间左闭右开，端点满足 `0 <= start <= end <= len`；元素为引用时依然共享对应元素对象。没有隐式 Python 负索引。外部 ndarray/Tensor 下标保持绑定声明的外部语义，不能套用 Vec 规则。

`std/vec` 提供创建、长度、容量、reserve、push、pop、resize 和 clear。容量属于共享的容器对象；pop/clear 保留容量。make/resize 的填充值按普通复制规则复制，因此填充值为 Vec 时，新增元素共享同一个内层 Vec；需要独立内层容器时逐个创建。活跃遍历中，不改变长度和存储的 reserve/resize 无操作可以执行；会扩容的 reserve 与改变长度的操作必须先 Panic。

string 必须是合法 UTF-8，长度、索引、切片按 Unicode 码点计数；索引返回 u32，组合符单独计数，不做规范化。支持动态 `+`、整体 var 的 `+=` 和值比较，索引及切片越界 Panic。`std/text.bytes` 返回 UTF-8 字节副本，`from_bytes` 拒绝非法编码并 throws text.Error。动态字符串与切片可以共享不可变存储，复制和清理保留其存活；字面量可以没有运行时拥有者。这些运算不增加 const 的编译期执行范围。

Vec 对象或元素存储分配失败，以及分配大小计算溢出时，产生 Panic，不转换成源语言 typed error。按第 8 节规则，不保证 Panic 后执行语言清理。

Vec 遍历使用进入循环时的长度，每轮读取当前索引元素并取得本次迭代所需的逻辑拥有值。活跃遍历期间，任何改变该 Vec 长度的操作必须在修改发生前产生 Panic；通过共享别名改变元素值仍可观察。实现维护活跃迭代状态并在结构修改入口检查，不能仅在下一轮比较长度而漏掉“修改后立即 break/return”或“删后再补回”等情况，也不能保留因扩容失效的裸元素指针。

struct 按字段声明逆序销毁，enum 按活动载荷字段逆序销毁，Vec 对象最后释放时按元素索引逆序销毁。部分构造失败仅销毁已完成初始化的字段/元素，顺序与其初始化相反。对外部 Python 对象，宿主析构时机不属于本语言的跨后端保证；确定资源释放必须使用显式 defer 或受控包装协议。

`py.Error` 可作为 `Vec` 元素、struct 字段和 enum payload 保存，也可位于嵌套泛型值中；它支持普通复制、整体 move、返回、越过 catch 继续持有以及再次 `throw`/`catch`。复制共享同一个语言 Error 载荷和原 Python `Exception`、cause、traceback 对象，不做异常深复制；语言 drop 只释放该拥有槽，不承诺 Python 立即析构，也不依赖 `__del__` 执行语言清理。上述容器的既有复制/销毁顺序、move 后不可读和部分 move 限制不变。普通外部引用（如 ndarray/Tensor）和 `py.Error` 的聚合保存只在对应 Python 后端范围开放，不扩大 Native FFI；外部 callable 仍不能作为聚合成员保存。

std/map、std/set 是以共享 Vec 实现的有类型容器，复制共享同一容器。std/json 的 Number 保存十进制原文，需要时显式转换；数组和对象最多嵌套256层。Native C 绑定支持有类型的 Ptr/PtrMut 和 Buffer/BufferMut，指针与缓冲区索引必须在 unsafe 块中进行；Buffer 检查长度，Ptr 的有效地址和生命期由调用者保证。

Native/64 和 Python/64 提供 `Slice[T]` 和 `std/slice` 的 `view`、`len`、`sub`、`to_vec`。视图使用半开区间，持有 owner Vec 并保护其存储；共享别名在视图存活时改变长度或扩容会先 Panic。Slice 切片产生子视图，Vec 切片继续复制元素；`to_vec` 新建容器并按普通规则复制元素。两后端均按普通规则复制和清理 Slice；Python 还会在循环回收时处理视图持有的 owner。字段和索引的可写 POD 位置已支持 `inout`；拥有值的容器本身、string、外部对象和函数值仍不能作为 `inout` 数据类型。

Native C 函数按绑定声明的固定签名调用，错误码是普通返回值，不自动转成 throws 或 py.Error。C resource 的每次拥有复制调用 retain_symbol，每个拥有副本清理时调用 release_symbol，由库决定最后一次引用释放时的析构；未声明 retain_symbol 的普通复制会被拒绝。借用指针和 C record 不自动释放目标。具体声明及限制见 [调用 C 库](FFI.md)。

### 7.2 参数模式和移动

- 普通参数不消费调用者拥有值。调用期间保证值存活；如果被调用方返回或存储参数，必须生成合法 copy/retain 使新持有者获得自己的所有权。普通参数绑定只读，不能给参数名重新赋值；需要改值时显式创建 var 局部变量。对象内容能否修改继续按其类型和已声明操作的规则判断，不因参数绑定只读就改变。
- `move` 参数消费一个拥有值。对已有绑定必须显式 `move x`；被移动绑定在重新初始化前不可读。初期只允许整个拥有绑定或临时值，不实施部分字段移动。
- `inout` 参数独占可写存储访问，不得逃逸、保存到对象或被捕获。可写位置包括整体 `var`、已有 `inout` 参数、其字段链（如 `obj.nested.field`）和可绑定容器元素（如 `items[i]`、`items[i].field`）。位置类型限定为数值/bool 或递归只含平凡值的有限 struct/enum；容器本身、string、外部对象、函数值和含拥有字段的聚合仍不能作为 `inout` 数据类型。索引位置的接收者可以是通过 `let` 持有的 Vec/Slice（元素写入修改共享容器），但字段位置的基础绑定必须可写；位置最终必须能追溯到本地或参数存储，临时容器不作为可借用根。
- 同一调用中不能把重叠存储同时作为 `inout` 与另一种访问传入。不同的具名字段可以同时作为非重叠 `inout`；相同或前缀字段路径、整容器访问、以及同一容器的动态索引继续保守拒绝。不同字面量索引可证明不重叠时可以同时借用。Vec/Slice 是共享句柄：复制到其他绑定、struct 字段、enum 载荷、函数返回值或闭包环境后，源码 SymbolId 不同不能证明对象不同。元素地址借用期间，其他实参若可能携带同一容器（包括间接 callee 的未知捕获环境），编译期保守拒绝；不得为未知别名生成 noalias。
- 索引 `inout` 在进入被调用方前完成一次边界检查，并将元素地址（或元素字段地址）传给被调用方；不复制整个 Vec 或聚合。typed error 和正常退出都在销毁拥有临时值之前结束借用，借用位置本身不产生额外 destroy，因此不应双重释放。当前只开放平凡 POD 位置；Vec/Slice 容器整体、string、函数值和含拥有字段聚合的 owning 非 POD `inout` 尚未实现。
- 默认参数的内部借用不能被直接 `move` 消费。必须先取得合法的本地逻辑 copy，再移动该拥有值。

闭包在创建时捕获它实际读取的外部局部绑定。捕获值是当时的逻辑副本：数值等直接值复制，Vec、Box、函数值等共享对象保留同一对象并增加引用。捕获绑定在闭包内只读；共享对象仍可调用已有接口修改内容。普通 `func` 复制每个捕获值；`move func(...) { ... }` 对每个实际捕获的拥有值执行 move，不提供逐变量捕获列表。

闭包可以保存、返回、传参和放入容器；捕获环境随函数值一起复制和销毁。`move func` 捕获后，被移动的原绑定在重新初始化前不可读。

方法值在创建时保存接收者的逻辑副本。普通 Self 和 move Self 都可以绑定成函数值；move-Self 的绑定值可复制并重复调用：每次调用先按普通规则复制保存的接收者，再把该副本交给方法。不能复制接收者时，绑定 move-Self 方法被拒绝。inout-Self 方法不能作为函数值保存。

### 7.3 运行库边界

原生 IR 使用 copy、move、borrow、end_borrow、destroy 等语言操作；LLVM 后端将需要的引用操作降低到 runtime retain/release。具体函数名可统一采用 `lang_rt_retain`、`lang_rt_release`，对象头布局由 runtime 与 lowering 共同拥有，不暴露为源语言 ABI。

引用计数为 0 时调用类型专用 drop，再释放对象存储。计数溢出产生 Panic。retain/release/drop 不能传播源语言 typed error。所有权优化必须保持析构的可观察顺序和清理约定；不能以性能为理由提前释放仍被借用的对象。

Linux x86_64 Native 程序允许在线程间共享 Vec 等对象。ARC 引用计数与内部迭代计数使用原子操作；引用计数只保证对象存活和最后一次清理安全，不保护元素和结构修改。共享对象的读写由程序员使用 Mutex 等同步；未同步的数据竞争属于程序错误，不保证结果。读取拥有元素并取得其引用也必须与替换该元素同步。

`std/thread.spawn[A]` 先支持无捕获的 `func(A) i64` 加明确参数，不接受 throws 入口。参数按正常复制规则持有到入口返回并完成清理。Thread 复制共享控制块，多次或并发 join 返回相同 i64；等待自身抛 os.Error。最后一个用户句柄清理不等待线程，线程结束自动释放资源；main 返回与 Panic 仍终止整个进程。`std/sync` 提供非递归 Mutex、Condvar 和固定顺序一致的 AtomicI64；锁误用 Panic，正常锁操作不抛错。具体接口见 [线程与同步](CONCURRENCY.md)。

`std/process.fork` 采用 POSIX 规则：子进程仅保留调用线程，运行库恢复自己的创建进程、环境和分配器锁，不重置业务锁。消失线程的未完成 Thread 句柄返回 os.Error；已完成句柄仍保留结果。fork 复制 ARC 计数，不能自动扣除消失线程持有的引用；这些引用可能保留至 exec 或进程退出，不会擅自执行其他线程的清理。通常在子进程立即 exec。

`std/ipc.Memory` 的句柄元数据属于各进程的普通 ARC，映射内容为 MAP_SHARED；同一进程的最后句柄释放时解除该进程的映射。共享内容只保存字节、整数和进程共享同步对象，不保存进程私有 ARC 指针。Mutex/Condvar/Semaphore 由程序显式初始化和销毁；进程退出不会自动恢复它持有的锁。正常锁操作不抛错，误用 Panic；定时等待超时返回 false。映射文件被并发截短仍可能触发 POSIX SIGBUS。信号支持同步等待及默认/忽略处理，不执行异步语言回调。接口见 [标准库](STDLIB.md)。

Native 与 Python 后端都会自动回收由 Vec、Box 和闭包环境形成的纯 Woozy 强引用环，在分配压力下的稳定点和正常 runner 退出时处理，不保证某个源码作用域退出时立即回收。涉及任务或协程帧的环和异步调用的普通参数保活尚未完成，不能据此认为所有纯 Woozy 环都可回收。具体测试范围见 [LANGUAGE_DOC_FACTS.md](../development/docs/LANGUAGE_DOC_FACTS.md)。外部 Python/C 对象自身的环仍由宿主管理。

## 8 typed throws 与 Panic

`throws E` 是函数类型的一部分，E 可以是普通枚举。一个函数的已声明错误类型必须覆盖其未捕获调用；原生类型以精确匹配为基线，跨类型转换显式完成。`Result[T,E]` 不参与自动传播。

原生内部降低采用成功标记及 value/error 两个输出通道。成功仅初始化 value，失败仅初始化 error；非活动侧禁止读取或销毁。这个内部调用约定未承诺二进制稳定；不能直接用作 C/C++ 公共 ABI。

Python 生成代码可通过专用异常承载源语言 typed error。编译期按 TypeId 检查匹配，生成产物用稳定逻辑类型身份或生成的类型对象匹配；会话内 TypeId 裸编号不能写入跨模块缓存。外部 Python `Exception` 在绑定边界转换为 `py.Error` 并保留 cause/traceback。`py.Error` 与其他拥有值一样可存入 Vec/struct/enum；复制共享原异常对象，清理不保证宿主立即析构。不捕获所有 `BaseException`；KeyboardInterrupt、SystemExit 以及本语言 Panic 不能被误包装。

Panic 表示除零、非法移位、越界等不可由 typed catch 恢复的运行失败。native 顶层终止程序；Python 使用 `langrt.Panic`（BaseException 子类）由生成的顶层 runner 转为失败诊断。两端不保证 Panic 后执行语言清理；Python 生成的 finally 必须避免把 Panic 路径误当普通错误路径执行语言 defer。由 Python 自身触发的对象析构也不作为可移植清理承诺。

错误离开 main 时输出错误诊断并以非零状态结束。正常 `main() i32` 返回整数状态，`main() Unit` 返回成功；支持是否声明 typed throws。程序退出码不与 `woozyc` 检查命令退出码混为一谈。

## 9 defer 和销毁顺序

`defer` 注册在当前词法块，退出时后注册先执行。它在普通执行流经过声明处才激活；未经过的分支不注册。defer 读取执行时的绑定值，需要快照时用户必须显式建立新绑定。

块退出时先按 LIFO 执行该块激活的 defer，再按声明逆序销毁仍拥有值的局部绑定；然后离开外层块。被移动值和未初始化变体不销毁。defer 执行期间其访问的局部仍存活；若其捕获绑定已被移动且未重建，所有权检查报错。

正常退出、return、break、continue、typed throw 都按实际退出的块执行该过程。continue 不退出循环外围作用域，但要退出本次迭代内层块；catch 进入前先清理 throw 所离开的块。

defer 不得向外 return/break/continue，也不得向外传播 typed error；其内部可以用 try/catch 消化错误，可以使用自己的内部循环。drop 同样不允许抛出 typed error。

Python 实现应生成与这些词法块对应的 try/finally 或等价结构，不能依赖 `__del__` 或函数级一个 finally 来代替全部块级清理。Panic 路径按第 8 节的无保证规则隔离。

## 10 Python 和外部能力

Python profile 只接受其能力表声明的源语言操作。原始地址、原始 syscall、未映射 C++ 类型不允许静默擦除。`unsafe` 不关闭类型/效果检查，也不让未支持能力自动可用。

ndarray/Tensor 的 shape、device、动态 dtype 和运行状态默认是运行时约束。绑定可表达已知参数类型，但不声称由静态类型保证矩阵乘一定可执行。`model(x)` 保持 Python 对象调用，不能改成 `.forward(x)`；不隐式调用 `.item()`、`.detach()`、`.cpu()` 或 `.numpy()`。

所有来自外部的必需信息都通过声明和显式调用获得。检查器只解析绑定文件；绑定的正确性需要独立 conformance 测试，不能由 schema 合法就推定真实库接口匹配。

## 11 优化约束与验收

默认关闭 fast-math；回绕整数无条件禁止 `nsw/nuw`。`noalias`、`nonnull`、`inbounds` 等仅在经过证明或明确 ABI 契约保证时附加。IR verifier 通过不是语义正确性的证明。

每条实施默认规则至少有一个正例和边界例；涉及资源的规则还需正常/错误控制流测试。两后端差分以公共子集为限，必须另有独立预期值，避免两个后端共同实现错了还互相通过。

## 闭包与 Weak

闭包捕获创建时的逻辑值，捕获绑定只读；Vec 等共享对象的内容仍可通过已有接口修改。普通 `func` 复制捕获值，`move func(...) { ... }` 移动全部实际捕获的拥有值，不提供逐变量捕获列表。

绑定 `move Self` 方法产生的函数值可复制、可重复调用。每次调用先按普通规则复制接收者，再把该副本移交给方法；不能复制的接收者禁止绑定。不增加只能调用一次的函数类型。

`Weak[T]` 是内建类型；`std/weak` 只提供 `empty`、`downgrade`、`upgrade` 操作。Weak 接受 Vec、函数值、有引用计数的共享句柄和 `std/box.Box[T]`。普通按值 struct/enum、string、文件/套接字描述符及外部 Python/C 对象不直接作为目标。`weak.empty[T]()` 建立空弱引用，`weak.downgrade[T](value)` 从强引用建立 Weak，`weak.upgrade(w)` 返回 `std/option.Option[T]`；目标已经没有强引用时得到 `None`。Weak 不延长目标寿命。Box 是共享的可变值单元，复制 Box 保持同一个单元的身份；`box.new`、`box.get`、`box.set` 已支持 Native 和 Python。
