# Linux x86_64 原生程序运行支持

默认 native/64 输出通过自己的 `_start` 进入语言 `main`，使用静态 ELF。链接时使用 `-nostdlib -static`，不链接 libc、libstdc++、C 启动对象或动态加载器。编译器本身仍使用 C++20 和 LLVM；随程序静态链接的私有辅助代码也用 C++ 编写，调用 Linux 系统调用，不使用 C/C++ 标准运行库。

启动时从 Linux 初始栈的 `AT_RANDOM` 取得栈保护随机值，设置 x86_64 的 FS 和 `FS:0x28`。随机数据缺失、值为零或 `ARCH_SET_FS` 失败时，向标准错误输出 `LANG_NATIVE_STARTUP_ERROR` 并退出 127。入口初始化代码不先读取尚未设置的栈保护槽。

Vec 存储由自己的分配器管理：不超过 4080 字节且对齐要求不超过 16 字节的小对象，复用匿名映射的 64 KiB 页内空闲块；大对象单独 `mmap`，释放时 `munmap`。每个大小类别最多保留一个空页供后续分配复用。大小计算溢出或分配失败按语言规则 Panic。元素存储按 16 字节对齐，覆盖当前支持的标量、指针和 struct/enum 布局；不支持用户指定更高对齐。

索引接收者属于普通参数且下标或赋值右侧不会消耗、替换该参数时，可以借用参数的已有句柄。局部 Vec 的直接读取也可借用：元素不含拥有值或类型参数，下标是整数字面量或整数变量，且整个完整表达式不会 move、inout 借用或重新绑定该 Vec。其他局部读取及 move 参数仍保留必要临时副本；字段、计算得到的接收者和写入沿用原规则。元素含拥有值时，读写继续执行相应复制和清理；纯值元素直接生成经过长度及初始化范围检查的 LLVM load/store。赋值目标仍在右值求值前检查，store 本身也保留检查，优化器可以消去已证明重复的检查。

Panic 和入口 typed error 使用直接 `write` 输出，短写继续写剩余字节，`EINTR` 在原位置重试。退出使用直接系统调用。运行支持自行提供 memcpy、memmove、memset、memcmp 和栈保护失败入口，避免编译器产生的辅助调用重新带入标准库。栈保护失败输出 `LANG_NATIVE_PANIC:v1:stack-corruption:0:0:0` 并退出 101。

每次检查独立性都要查看最终 ELF 的解释器、动态段、依赖和未解析强符号，并实际执行正常结束、Panic 和错误程序。只看静态链接选项或 LLVM IR 不足以确认。用宿主 C++ 观察器链接的测试程序仍可依赖 libc，不能拿它证明公开 CLI 输出独立。

本实现只覆盖 Linux x86_64 和当前已支持的语言功能，不提供其他平台启动代码、线程运行支持或任意 C/C++ 外部库兼容性。标准库扩展仍按用户要求后移。
