以下改动已应用到工作区。数据来自 Linux x86-64 Native O2。倍数对应各自的手写 C++ 对照和所列负载。CPU 时间和墙钟时间分别记录。

| 改动 | 实测结果与覆盖 | 仍需核对 |
| --- | --- | --- |

旧 Map/Set 补丁退回。允许的哈希回调重入可以使长度少算，墓碑也可能占满整张表。旧 C++ 对照使用了 `std::vector`。

读写锁候选通过 16 项功能测试，无争用 CPU 时间下降 37%–45%，混合争用复测出现相反结果。JSON 字节扫描在短 ASCII 对象和长 Unicode 字符串上提速，转义组在 seed 中位数变慢，且缺 Python 回归。这两项候选保留待复测。

从合并后的源码重建 LLVM 22.1.8 种子编译器。选跑 **44 项全通过**，包括 O0/O2、Python 容器和文本、正则、Unicode、CSV、排序、文件及 I/O 错误。完整 CTest 和各平台延迟仍未验证。

JSON 解析、读写锁和 Channel 的候选存在少数负载的回退或不稳定结果。GC poll 原型对取消查询有反复测到的收益，合入前还需两套编译器生成代码的回归测试。整数及浮点解析的 Wz 原型已保留，公开入口尚未切换。

### HTTP、DNS 和容器复测

- HTTP 解析改用字节区间处理请求行、头和 trailer。两种固定长度 POST 的中位耗时从 14.874 降到 8.436 µs，快 43.3%，仍为手写 C++ 的 13.28 倍。合并后的 Native O0、O2 分别通过 26 项。原有 trailer 字节数恰好到上限时的错误差异仍待修复。
- 数值 DNS 直接把解析得到的地址 Vec 交给结果。IPv4 查询中位耗时从 273.95 降到 214.92 ns，快 21.5%，仍为 C++ 的 4.13 倍。合并后 DNS 和网络两项运行库测试通过。Darwin 共用源码，尚未在实机重跑。
- 合并版种子编译器用手写 Clang O2 对照复测 Vec、Heap 和两种容量的 Deque。9 轮交替运行均通过结果核对。524288 元素的 Deque 尾插这批为 1.35 倍，两个末端删除为 5.98–10.96 倍。四项 Heap 为 2.82–9.77 倍。主机负载影响较大，数据用于定位，仍需独立低干扰复测。
- 退回新 Set 候选。Python 产物在稳定哈希、稳定相等关系下仍可复现回调重入后的错误长度、漏查已有键和 Vec 越界。
- 第一代按包构建 360 秒超时。常规项目构建也在种子编译器的 Native 辅助程序中 900 秒超时，进程已清理。第二次构建期间，种子编译器通过链接读取的 `stdlib/strconv/strconv.wz` 发生了变化，脚本已按输入变更和超时同时判失败。没有产生可验收的第一代编译器。

### Deque 清空和进程参数

- Deque 只取连续两段清槽和托管元素测试。原完整候选的回绕清空用时缩短 3.28–3.87 倍。补丁合并后的容器测试在 Linux Native O0、O2 和 Python 均通过，拆分后的耗时尚未复测。长短段的扩容策略仍沿用原实现。
- `process.args()` 改为按参数数目一次分配，只登记成功转为 UTF-8 文本的元素。24 对短 ASCII 参数原始试验中，耗时中位数从 44.66 ms 降到 31.31 ms，是手写 C++ 的 2.98 倍。仅 13 对低于或等于 3 倍。合并后的 Linux 进程、运行库、C 回调测试均通过。

### GC 轮询、读写锁和算法

- 两套 Native 代码生成器在原安全点直接读取停顿请求和 GC 压力。有请求时仍调用运行库。Linux O2 的 24 轮候选对照中，Heap 弹出为手写 C++ 的 1.55 倍，取顶为 2.10 倍，建堆为 2.03 倍，插入为 7.68 倍。取消标志查询比改动前快约 4 倍，仍为 C++ 的 7.43–7.67 倍。合并后种子编译器通过 GC 激活、7 组 Native O0/O2 循环回收和 9 组 O0/O2 单线程自动回收测试。自举发射器的独立验算 18 次通过，16 次核对了位置，漏插和错插反例均被拒绝。新编译器须与新运行库一起发布。此批已推送为 `701a9c8`。
- 用合并后的 Linux O2 编译器复测 Deque，两种输入各 7 轮，同轮核对操作数和校验值。各操作比集成前快 30%–57%。尾插为手写 C++ 的 1.07–1.39 倍，混合读取为 2.23–2.87 倍，前端增删为 2.27–2.30 倍，尾删为 3.63–3.66 倍。该批仍有四类操作超过 2 倍。
- 读写锁直接持有共享状态，固定保存第一位读者，更多读者再用 Vec。Linux O2 候选和手写 C++ 配对，大样本中单线程读写为 2.45–3.58 倍，一读一写为 2.28–2.61 倍，多写者为 3.65–9.25 倍。合并后并发脚本的 18 次构建与 26 次运行通过。
- Heap 弹出在首次比较前将末元素写到根，保持比较回调通过别名读取堆顶的旧行为。新测试覆盖别名读根和多层挪动 Box，合并后的容器测试通过 Native O0/O2 和 Python。冻结编译器上的 9 轮对照中，四项操作均快于原版，对手写 Clang O2 为 2.22–7.02 倍。该组耗时来自候选独立试验，未与合并后的 GC 轮询一起测。
- `fold` 每轮处理四项，5 对样本的 CPU 时间降约 44%，仍为手写 C++ 的 9.96 倍。稳定排序只在第一次需要归并时分配临时 Vec。放弃了让比较回调通过别名看到重复或缺失元素的双缓冲方案。合并版 Algo、Sort 和容器测试均通过 Native O0/O2 和 Python。
- 纯 Wz 整数解析此前反复扫描长非 ASCII 输入，16,384 个零后接一个 `é`，4 次有符号和无符号解析共用 1.782 秒，原 C++ 路径用 0.252 毫秒，两版都返回 `InvalidSyntax`。现已用字符串的字节数和码点数提前拒绝非 ASCII，同一输入在合并后实测中位数为 1.232 µs。本地 Native O0/O2 和 Python 均通过。

### JSON、数值 DNS、浮点格式化和 HTTP

- JSON 按 UTF-8 字节扫描，错误位置仍按 Unicode 码点计数。合并版 15 组容器和 JSON 测试及独立输出比对通过。四组 O2 解析样本比改动前用时少 34%–78%。大量不同键的对象仍逐项扫描。当前 C++ 对照使用了 `std::string` 和 `std::vector`，与 Woozy 的存储成本不同，不能用它判定达标。
- 直接解析数值 IPv4，避免二次构造并转移向量所有权。Linux DNS 和网络运行库测试通过。候选中的数值 IPv4 用时为手写 C++ 的 3.05–3.41 倍。
- `format_f32` 和 `format_f64` 已改用 Wz 的 Ryu 实现，保留许可证。独立验证中 19,716 条 Native O0/O2 输出与 C++ 逐字节一致，三个 Python 用例通过。原 Python 有六项改为更短的往返格式。普通值和次正规值的候选耗时仍约为 C++ 的 3.06–3.99 倍。JSON、DNS 和浮点格式化已推送为 `7b98857`，整数代码未进入此提交。
- HTTP 合并了头分类、framing 检查和扫描，固定长度 POST 候选从 5.60 降到 4.28 µs，仍为手写 C++ 的 9.51 倍。合并后 Native O0/O2 各通过 26 项，包括非 ASCII trailer 的字节上限。此批已与整数转换一起推送为 `1a1926b`。

### 第一代自举和整数转换复测

- 用物理复制的种子编译器、辅助程序、运行库和标准库出第一代，按包构建、O0、输入哈希未变化，耗时约 25 分钟。第一代产物为 `woozyc 0.1.0-selfhost`。用该编译器编译本轮容器和数字用例，Native O0/O2、Python 共 6 项通过。Native O2 跟踪核对了实际标准库和运行库路径，没有调用种子辅助程序。
- 13,388 项整数解析、格式化和错误结果在独立种子编译器的 Native O0/O2 下与原 C++ 入口逐字节一致，覆盖各长度、长前导零、边界相邻值和十进制进位。
- Linux x86-64、CPU 13、Native O2。短值和全宽值的有符号、无符号转换各测读写，共 8 组，每组 3 对进程交替、每次 7 个计时样本。各组校验值一致。独立种子编译器生成的程序为手写 C++ 的 1.41–2.03 倍，第一代自举编译器产物为 1.45–1.82 倍。

### Unicode 大小写、Set 清空和 Vec 复制

- Unicode 的 `casefold`、`upper`、`lower` 改用 Wz 和按版本固定的 Unicode 数据。两套编译器生成的 Native O2 和 Python 程序均通过定向测试，种子编译器生成的程序核对了 1,112,064 个 Unicode 标量的大小写折叠结果。八组 `casefold` 输入各交替计时七轮。种子编译器产物用时为同一公开入口旧 C++ 实现的 0.114–1.061 倍，第一代产物为 0.116–1.126 倍。八组耗时只用于评价 `casefold`。大小写转换已推送为 `c4075df`。
- Set 的开放寻址候选在 6,000 次「插入 256 键、清空」后峰值 RSS 为 131,544 KiB，主线为 12,012 KiB。候选每轮从小表重新扩容，但未释放或复用历史槽位。该改动暂缓提交。复现的原始数据保存在 `set-clear-memory/measured-rss.json`。
- Vec 容量内追加和常见定宽元素的复制改动在隔离版本通过 `native.vec_growth` 和 `native.vec_runtime`。检查运行库对象，未引用 libc 的 `memcpy`、`memmove`。候选在种子和第一代编译器生成的程序中，`i32` 尾插少用约 19%–21% 时间，弹出少用约 34%–36%。弹出仍约为带 pin 检查的手写 C++ 的 4.1 倍，直接访问仍有 7–11 倍的样本。改动前后的配对数据在 `/tmp/woozy-sol62-final/minimal/paired-summary.tsv`。
- JSON 的大对象使用局部哈希表检测重复键。两个编译器各通过 15 组集合用例和 JSON 独立输出对照。保持第一次插入的位置和最后一次赋值。1,500 个不同键的独立试验中，每次解析从 73.3–75.5 ms 减到 1.13–1.42 ms。同类索引的手写 C++ 参考仍快约 9.3–10.1 倍。该参考的哈希、扩容、UTF-8 校验和内存分配与 Wz 不完全相同，不能用这个比值判定等效实现是否达标。四种键的转义及重复输入用时少 8%–16%，余下耗时集中在每个字符串的分配、复制和校验。

- JSON 和 Vec 已推送为 `f7438b7`。隔离主线候选的 8 项 Vec/Slice 测试通过。Linux Clang 22 的 O0 对象仍有一处 `lang_vec_new_v1` 的旧 `memcpy` 引用，对照对象同一处也有。O2 的两个对象均无此引用。

### 字素边界和 Set 重入

- `unicode.boundaries` 改用 Wz，仍返回码点下标。两代编译器的 Native O0、O2 和 Python 各通过 Unicode 18.0 的 853 个官方用例。种子编译器的两个 CTest 均通过，官方用例在本次 CTest 中耗时 65 秒。生成表与捕获的 Unicode 数据核对通过，包外调用内部扫描器会报 `E_PRIVATE_ACCESS`。先前六组样本的用时为旧 utf8proc 路径的 0.56–0.93 倍。C++ 参考仍使用 `std::vector`，其 ASCII 样本差距仍大，暂不据此判断 3 倍目标。已推送为 `794e00c`。
- Set 改用共享开放寻址表，修复 clear/refill 历史表累计及 equals 回调重入时查询和重复插入的返回规则。6,000 轮插入 256 键后清空，隔离种子实测峰值 12,172 KiB。新增回归接入集合测试，种子编译器 18 项加 JSON 独立对照通过，第一代定向回归通过 Native O0/O2 与 Python。Linux Native O2 的配对样本中，32,768 键时删除命中为手写 C++ 的 2.11–2.28 倍，另十项为 1.29–1.96 倍；100 万键时种子命中查询为 2.08 倍，另 21 个编译器与操作组合为 1.22–1.92 倍。已推送为 `9d82057`。原始记录见 `set-final/perf-*.json` 和 `set-final/set-clear-final-rss.json`。

### 浮点解析和 JSON 临时缓冲

- `parse_f32`、`parse_f64` 改为 Wz，精确比较处理长度截断、次正规数、溢出和平局。种子 Native O0/O2 和第一代 Native O2 的 80,166 项输出与基准逐字节一致，另用 Python Fraction 独立重新计算了全部结果。两代的 Native O2 加种子 O0 也通过了 96 项正负、1,200/1,600 位十进制舍入中点样本。两个 Native O2 对象未引用旧 C++ 浮点转换入口。核对了 651 对 fast_float 表值，包内带来源、作者和原许可。第一代 Native O2 的六组常见数字样本，中位数为同算法手写 C++ 的 2.48–2.76 倍，p90 为 2.83–3.05 倍。已推送为 `a5063d9`。
- JSON 复用短键名和短数字临时字节缓冲的候选，两套编译器各通过 15 项集合测试和 JSON oracle。手写 C++ 新参考采用相同的索引阈值、码点哈希、UTF-8 校验和拥有式结果。纯解析的两个样本分别为 5.73 倍（1,500 个不同键）和 4.48 倍（8,000 个转义及重复键），用时比当前 Wz 主线低 5.8% 和 20.4%。参考与 Wz 的分配器及运行库不同。候选还在测空对象、独立字面量等不会反复使用临时缓冲的输入，暂未推送。

### 字素切分的线性候选

- `unicode.graphemes()` 的逐字节游标候选在种子、第一代的 Native O0/O2 和 Python 中，各逐片段核对了 Unicode 18.0 的 853 个用例，以及包含 NUL、CRLF、Indic、非 BMP 字符和空串的补充输入。
- 两代 Native O2、CPU 14，每个样本七轮配对并核对输出数和校验值。同原 Wz 实现相比，1,024 个重复 `é` 的耗时约为 0.059–0.061 倍，8,192 个约为 0.008 倍，1,024 组混合文本约为 0.007–0.008 倍。ASCII 的短、长两组反而用时 1.79–1.99 倍，短 `é` 样本为 1.25–1.29 倍。这次是新旧 Wz 对比，仍缺与等效手写 C++ 的对照。
- Native 原切片会保留同一字符串的所有者。该候选通过 `text.from_bytes` 为每个片段分配并复制数据。暂缓原候选，继续试验从字素边界逐段生成共享视图的做法。Python 原切片已经按字符下标取本段，连续复制剩余后缀会引入额外开销。原始记录在 `graphemes-split.q3F6w1At/split-performance.json`。

### 主线源码直接调用的内建函数
