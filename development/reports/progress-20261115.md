## 当前结果

Woozy 自举第一代编译器已经能够运行，旧 d602 版本的 985 个已启用用例全部通过。完整自举尚未完成：旧正式版第二代触发了 6 小时超时，旧私有 GC 版第二代发生段错误。新的 db918 第一代已编译成功（1076.241 秒），第二代正在编译。新源码的 985 整组测试已跑完：985 通过、0 失败，104,514 项独立检查无错误，已按原 985 组接受；async 参数 11 专项已独立接受，其余专项仍在推进。

旧私有版本段错误的直接原因是栈耗尽：原 core 里 74 层 `nativelower.stmt` 占用了约 15.68 MiB。将 13 个分支拆出后，实测 dispatcher 栈帧从 222,192 字节降到 10,576 字节；不过直接 for_in 递归含参数仍占 45,600 字节，不能据此推算所有递归形态的安全深度。同样在 16 MiB 栈下，80 层嵌套输入在旧组件上崩溃、在新组件上通过，7 个原 fixture 的完整 IR 检查和 28 次二进制运行也全部通过。但原完整 Source 能否跑通仍须新的三代自举来证明，且目前没有证据表明 GC 扩桶引发了原故障。

- 本轮源码与测试核对以本机及私有远端仓库 `main`（`7a79db7ce098267817f67a318835d28f64c20c6a`）为起点，后续只改了下文列出的两处产品源码及对应测试记录。
- 当前 116 份 Woozy 源码清单的指纹为 `db91835d1c723d6ebfd0f0256a858a0cd4f8e51372cb8a03d06a3a9b279da749`，其中只修改了 `stmt.wz`。实现提交为 `eab3674`，源码指纹提交为 `c330a13`。
- GC 桶数从 2048 调整到 16384 已合入同一实现提交。配套种子 6761 与 helper 23e6 已重新构建，实际运行库为 5ff/7c20，没有拿旧种子换标签。
- 当前清单共 1350 项：985 启用、365 停用、243 required，涉及 2911 个记录文件和 275 个测试脚本。`55d45f8` 发布了已审通过的 23 项完成信息，原 985 组的对象、预期和预算均未改动。

- 新三代首次启动在输入核对阶段即中止，未启动任何 Source 编译进程：原因是 Root 的普通 Python 导入写入了被忽略的缓存文件。该缓存保存后已恢复，Root 也实测确认禁用缓存写入的读取不会改变输入，旧失败目录原样保留。唯一修正任务在新目录中编译同一份源码，每代 21600 秒预算、O2 和 16 MiB 栈限制均保持不变；第一代于 22:07:43 开始、22:25:39 成功结束，第二代于 22:25:49 启动（北京时间）。命令运行期间状态文件的 setup 字段尚未刷新，实际进度以 launch 记录和进程为准。

两个旧任务均已结束，不再算作 running。两版第一代的制作耗时不同，不能用来推断 GC 修改带来的性能变化。

私有版本已有匹配的 core dump：递归函数 `lang.fn.2903` 每层至少占 222,192 字节（约 217 KiB），经 `lang.fn.2827/2828` 进入 `lang.fn.2843+0x21`；在调用 `lang_gc_runtime_poll_v1` 压入返回地址时触发段错误，fault 地址为 RSP-8，低于 16 MiB 栈映射下界 1704 字节，此时尚未进入 poll。正式版与私有版第一代的 program.o 逐字节相同（SHA 前缀 52370e9），说明这个大栈帧同样存在于正式版生成代码中。基于原冻结输入的 resolve-only 检查已确认这四个符号分别对应 `stmt`、`expr`、`raw_expr` 和 `node`，独立复核 309 项文件及原始流 SHA 均无差异。原 `stmt` 函数共 775 行，拆分后的局部机器帧缩减和深输入对照已经实测，但完整 Source 能否通过仍要等新三代验证。现有证据还不能证明正式版超时最终会停在同一位置，也不能据此判断 GC 桶数与故障存在因果关系。

失败未能及时上报的原因也已查明：这两项任务由 Root 直接在后台拉起，脚本只写 completion.json、未接入 Bridge 完成事件，Root 也没及时去读终态。后续长任务统一改由 Bridge operator 前台执行，保持原每代预算并给足整项任务总时限，由 Bridge 发送完成事件。可控 exit 7 通知事件 962807 已由当前原生会话收到，Root 核对实际记录后已完成 ACK。不过该通知测试实际执行了两次：首次未能序列化记录，第二次才完整保存 `7/false/true/false`；由于未满足“一次执行且不重试”的要求，这次交付已被拒绝且不再重跑。第二次记录和本次真实收到通知仍然有效，但不能据此承诺忙碌会话总能即时收到通知。具体执行要求见 [长任务说明](../LONG_RUNNING_TASKS.md)，不额外新增定时器或通知服务。
