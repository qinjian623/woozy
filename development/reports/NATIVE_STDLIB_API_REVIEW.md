# Native 标准库接口审查

AGY 使用 `gemini-4-neon-xhigh` 审查了 `d3cf8f6` 上的开发快照。比较对象包括 C++23 和 Python 3.14，代码范围包括七类库、HTTP 流式编解码候选和任务组首版。本轮交付目标为 Linux x86_64 Native。审查建议与运行结果分别记录。 [开发计划](../plans/NATIVE_STDLIB.md) · [C++23 草案](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf) · [Python 3.14 标准库](https://docs.python.org/3.14/library/)

| 范围 | 审查发现 | 处理方式 |
| --- | --- | --- |
| 容器和算法 | 堆比较函数的注释方向有误。有用户回调的下标循环允许通过别名改变 Vec 长度。键排序反复取键。 | 堆和算法增加遍历保护，保留现有元素的复制规则。键排序按输入顺序取键，每元素调用一次。新增 API 统一命名。 |
| 文本和正则 | 格式串 `{:8}` 被拒绝，有些带 `0` 的宽度会按空格处理。正则的捕获和普通匹配需要分别编译，字段下标也容易用错。 | 明确宽度和对齐规则，限制单次输出长度。评估共用 Pattern，保留普通匹配的低分配路径及已有正则限制。Unicode 大小写使用固定版本的官方数据。 |
| 文件系统 | 显式指定符号链接目录为根时，遍历只返回链接本身。有效名称已经解码，但接口仍要求处理原始字节。 | 新的 `walk` 解析用户指定的根，后代符号链接仍按项返回。有效名字用字符串，解码失败保留原始字节。目录复制和删除使用描述符相对操作。保留已发布 `read_dir` 的行为。 |
| CSV 和 JSON | CSV 的未终止引号字段可持续占用内存。JSON 整数转换把语法错误当成越界，手工对象的重复键查找与解析器不同。 | 增加字段和记录限制，并检查异常恢复的写入进度。JSON 区分无效整数和越界，字段查重保留最后值。 |
| HTTP | 分段读取把字节上限当成填满目标，短数据可能一直等不到下一段。异步 handler 混用了正文超时。 | 读取到已解码数据时按上限返回。补用真实连接测试短数据、背压、尾部字段、提前响应和连接复用。handler 超时需要保留已发布同步配置的用法。 |
| 并发 | 首版任务组依靠轮询。重复等待、外部取消以及父任务被取消后的清理顺序有漏洞。 | 首版暂未合入。运行库增加仅用于任务组的取消和清理规则。普通共享 Task 的等待保持原规则。验证父任务结束时，成员已完成清理。 |

保留设计包括 `Vec[bool]` 的普通元素规则、由 Slice 维持底层数据寿命、`Option` 表示查找缺失、严格区分 UTF-8 与原始字节，以及 JSON 保留数字原文。相较于 C++23，优先复用已有泛型和比较函数接口。相较于 Python，优先做到常用调用简短、类型清楚、错误便于处理。 [WG21 N1185](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/1999/n1185.pdf) · [WG21 P2017R1](https://open-std.org/jtc1/sc22/wg21/docs/papers/2020/p2017r1.html)

首轮检查覆盖了 Linux Native O0/O2 下的容器、算法、文件格式、文件系统、异步 handler 和 HTTP 编解码。任务组及流式服务器的后续结果见下文。

## 第二轮复审

Neon 用同一型号复审了修订后的 Linux 接口。纯 JSON 的数字转换、重复键和格式化规则在这次复审中无需再改。其余发现按当前工作区核对如下。

| 接口 | 当前处理 |
| --- | --- |
| `csv_io.write_file` | 文件函数在关闭内部 Writer 后统一报告 `Io`，失败时目标可能只写了一部分。Linux `/dev/full` 测试覆盖短行和超过缓冲区的长行。 |
| `csv.Parser`、`csv.Encoder` 和 `csv_io.Reader` | 构造函数名称已统一。`parser_finish` 成功后结束输入。Reader 副本在底层文件关闭或追加数据后继续返回 `None`。Linux Native O0/O2 已通过。 |
| `regex.compile` 与捕获 | 普通 `compile` 自动保留捕获，超过限额时仍可普通匹配，捕获接口抛出单独的 `CaptureError.Unavailable`。保留原 `regex.Error`，现有穷尽 `switch` 无需修改。普通与捕获测试均用 C++ 种子和 Wz 编译器在 Linux O0/O2 下通过。 |
| `fs.walk` | 根符号链接会被解析，有效文件名用字符串。目录按批读取，达到条目上限时报告截断，默认不限制深度。种子和自举编译器的 Linux O0/O2 测试通过。 |
| `fs.copy_dir`、`fs.remove_dir_all` | Linux 测试覆盖深目录、目录项分批读取、低文件描述符限额和并发改名。操作使用目录描述符，后代符号链接按链接本身复制或删除。C++ 种子和当前源码构建的 Wz 编译器都已在 O0、O2 编译并运行这些用例。目录复制的大测试拆为独立检查函数后，Wz O2 编译和运行约 29 秒，原断言和 LLVM 校验均保留。系统调用之间发生并发改名时，仍可能得到错误和部分结果。 |
| `http.read_request_body_part` | 短读修复及逐字节断点用例已在 Linux Native O0/O2 通过。标准库手册补了返回上限、重试和 chunked 编码规则。 |
| `http_server` | 候选改动把 handler 执行时限和正文读取时限分开。使用当前 C++ 种子和编解码代码，18 次普通异步连接和 26 次流式连接通过，包含同步配置兼容用例。候选仍需覆盖 handler 返回后挂起的读写，以及同一个流上重叠的读写。 |

复审快照漏带了修订后的 `std/io` 和 `std/vec`，因此报告里的缺少 `write_byte`、`extend` 只在该快照复现。当前工作区已有这两个函数，CSV I/O 和堆的 Linux 测试均已跑过。`write_byte` 刷新失败时新字节尚未进入缓冲，这条规则已写入标准库手册。

## HTTP 和任务组补充审查

Neon 复审了两项尚未合入的接口。HTTP 的公开 `Config`、`listen` 和 `listen_with` 保持原签名。一个流只允许一项读写操作在进行，重叠操作在修改状态前返回 `http.Error.ReadOrder`。流式响应用例还要验证 `Connection: close`、错误响应计数和优雅关闭期间的阶段超时。

任务组须接受同为 `Task` 的定时器和描述符等待。外部取消任务组时，等待成员清理后传播取消。仅成员取消时，其他成员已经产生的有类型错误仍需返回。多个错误按观察顺序选择，同一轮观察到的错误按输入顺序选择。用成员完成事件替代轮询时，还要测试已完成成员和开始等待前就收到的完成事件。

任务组已合入工作区。Linux x86_64 Native 的 C++ 种子和 Wz 编译器各通过 56 个 O0/O2 用例。通知改用成员完成事件，单独取消通知会释放登记时保留的引用。这个修复与 27 个已有场景一起通过了 ASan 和 UBSan 测试。两端的 227 个系统操作签名也通过了差异测试。 [任务组用法](../../docs/CONCURRENCY.md#等待一组任务)

流式 HTTP 已合入工作区，C++ 版和 Wz 版编译器在 Linux x86_64 Native 的 O0、O2 各通过 36 个场景。覆盖分段正文、背压、响应关闭、取消、fd 复用以及响应字节和请求计数。关闭 fd 前撤销事件监听，等待方的清理由执行器继续处理。测试确认旧 Stream 在 fd 编号已复用时收到 `ReadOrder`，新连接仍可继续读写。

Neon xhigh 又复审了流式超时。读按一次 `read` 调用计时，处理按两次 I/O 之间的间隔计时，写按一次公开的写调用计时。处理间隔每次 I/O 结束后重置。优雅停止时，各阶段的截止时间都受 `drain_timeout_ms` 限制。长流还可用 `Config.limits` 限制正文大小。配置从 `default_stream_settings()` 取得后按字段修改，三个毫秒参数无需按位置记忆。

固定大响应的头和正文现在共享一个写入时限。`100 Continue` 的写入截止时间也受优雅停止时限限制。取消挂起的读写时撤销原有等待，仍在运行的 handler 恢复处理时限。并发调用两次 `finish` 的回归测试确认一次成功、一次 `ReadOrder`，连接只收到一个结束块，服务端只计一次响应。

工作区的 Linux Native CTest 通过 87 项，包含七类标准库和新增流式服务器检查。流式测试在 Wz 下直接编译为静态 ELF，未调用 C++ 编译 helper。
