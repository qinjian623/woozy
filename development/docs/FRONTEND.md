# 前端开发契约

版本：0.1。本文规定待实现的 C++20 前端，不表示这些模块已经存在。现有 `baseline/tools/check_syntax.py` 仅用于词法和语法识别；不能作为名称、类型、效果或所有权检查器。

先读 [词法与语法基线](../../baseline/LEXICAL_SYNTAX.md)、[EBNF](../../baseline/grammar.ebnf) 和 [执行语义](../../docs/SEMANTICS.md)。本文件负责实现边界；运行语义以 `SEMANTICS.md` 为准。IR 数据结构见 [IR_CONTRACTS.md](IR_CONTRACTS.md)。

## 1 实现范围

- 实现语言：C++20；声明和语句使用递归下降，表达式使用 Pratt 或优先级爬升。
- 公共前端不得包含 LLVM、Clang、CPython 或 PyTorch 头文件，不得通过执行 Python、导入 Python 包或初始化 GPU 来检查源码。
- `check --syntax-only` 到 AST 为止；完整 `check` 运行当前目标所需的语义检查，但不优化、不生成目标文件、不调用链接器。
- CLI、LSP 和代码生成入口调用同一前端库。不得为编辑器维护另一套宽松类型规则。
- 所有已在文法中的构造都能被解析。尚未完成语义或后端实现的构造必须报告 `E_CAPABILITY_UNAVAILABLE`，不能生成猜测性的代码。
- 第一版不支持捕获闭包、动态包初始化、源函数重载或未声明的 Python 动态接口。动态 trait 对象的语法、对象安全和后端表示见 [TRAIT_OBJECTS.md](TRAIT_OBJECTS.md)。具体阶段范围以开发任务表为准。

## 2 阶段接口

以下为数据契约伪 C++，不是可直接编译的头文件。实现可以调整容器和内存布局，不得改变阶段输入、输出和不变量。

```cpp
SourceSnapshot load_source(FileInput, SourceManager&);
PhaseResult<TokenBuffer> lex(SourceSnapshotId, FrontendContext&);
PhaseResult<AstFile> parse(TokenBufferId, FrontendContext&);
PhaseResult<ModuleGraph> resolve_imports(ProjectInputs, FrontendContext&);
PhaseResult<ResolvedModule> collect_and_resolve(ModuleId, FrontendContext&);
PhaseResult<TypedModule> type_check(ModuleId, CheckOptions, FrontendContext&);
PhaseResult<VerifiedHirModule> verify_semantics(TypedModuleId,
                                            TargetProfile,
                                            FrontendContext&);
```

| 输出 | 必须包含 | 允许存在的未完成信息 |
| --- | --- | --- |
| `TokenBuffer` | token、trivia、源区间、词法诊断 | 错误 token；后续阶段不能把它视为成功字面量 |
| `AstFile` | 完整文件结构、所有节点位置、恢复节点 | 名字未解析、类型未确定、方括号候选未消解 |
| `ModuleGraph` | 逻辑模块身份、解析结果、导入边及其源位置 | 缺失模块记录；不能进入成功构建 |
| `ResolvedModule` | 声明、符号、作用域、类型引用的解析结果 | 类型变量和泛型参数仍可存在 |
| `TypedModule` | 每个表达式的类型、已匹配的调用、模式绑定 | 泛型参数；效果/所有权检查尚未完成的状态 |
| `VerifiedHirModule` | 对当前目标和功能配置已通过检查的 HIR | 未实例化的合法泛型声明；无错误/恢复节点 |

`PhaseResult<T>` 同时返回产物、诊断和 `complete / recovered / failed / cancelled` 状态。恢复成功仅供继续诊断和 IDE 使用；不能使 `check` 返回成功。代码生成只能接收 `VerifiedHirModule`，不得接收原始 AST 并自行补做类型推断。

## 3 源文件和位置

### 3.1 不可变快照

每次读取或编辑产生新的 `SourceSnapshotId`。一个快照持有原始字节、规范化文本、行索引和位置映射。AST、token、诊断和修复建议都引用产生它们的快照，避免把旧诊断应用到已经变化的文件。

```cpp
struct SourceSpan {
    SourceSnapshotId snapshot;
    uint64_t begin_byte;  // 原始文件，包含端点
    uint64_t end_byte;    // 原始文件，不包含端点
};

struct SourceSnapshot {
    FileId file;
    RevisionId revision;
    ImmutableBytes original;
    ImmutableUtf8 normalized;
    OffsetMap normalized_to_original;
    LineIndex original_lines;
};
```

### 3.2 编码和映射算法

1. 验证 UTF-8；原始 NUL、非法 UTF-8、独立 CR 分别产生词法诊断。非法 UTF-8 的位置仍以原始字节表示。
2. 跳过且仅跳过文件起始 BOM。保留其原始字节位置，不把后续 token 的原始偏移重置为零。
3. CRLF 规范化成 LF，建立规范化字节边界到原始字节边界的单调映射。CRLF 对应的换行范围覆盖原始两个字节。
4. lexer 在规范化文本上工作；创建 token 时立即映射成原始 `SourceSpan`。
5. 多行原始字符串的值使用规范化后的换行。诊断与编辑操作仍定位原始文件。

原始字节偏移是编译器内部唯一权威位置。CLI 展示时转换为一基行号和明确的列单位；LSP 按协商的位置编码转换，默认 UTF-16。不得直接把 UTF-8 字节偏移作为 LSP 字符偏移。修复建议附带快照版本及待替换原文；应用时检查版本与原文。

### 3.3 生命周期

`string_view` 只能指向仍由快照或字符串池持有的内容。诊断队列不得引用临时 lexer 缓冲区。一个前端查询结束后，结果通过拥有快照/arena 的结果对象保持有效；不得让客户端依赖全局可变 arena。

## 4 Token 和词法分析

```cpp
struct Token {
    TokenKind kind;
    SourceSpan span;
    InternedText spelling;
    TriviaRange leading_trivia;
    LiteralPayloadId literal;  // 非字面量时为空
};
```

- token 类型覆盖关键字、保留词、标识符、数字、字符串、运算符、错误及 EOF。
- 注释和空白保存在独立 trivia 序列。第一版可以不提供完整 CST，但不能在读取后永久丢弃注释和格式信息。
- token 按最长匹配识别。显式拒绝基线不支持的 `++`、`--`、`->`、`?` 等，不把它们悄悄拆成另一种合法表达式。
- 数字记录原文、进制和分类。负号保持为独立一元运算符，不能提前把整数文本强制装进宿主 `int64_t`。
- 常量范围检查使用前端自己的任意精度整数抽象或受控依赖；公共前端不能为了 `APInt` 而引入 LLVM。
- 字符串先校验转义和 Unicode 标量，再存解码后的 UTF-8 值；值允许包含转义产生的 NUL，源码原始字节不允许 NUL。
- `null`、`auto`、`fn`、`while` 是普通标识符；不能当作语言关键字或特殊字面量。
- EOF 必须唯一且源区间为文件结尾的空区间。

错误恢复必须保证每轮至少消费一个字节或到达 EOF。未终止字符串/注释应返回定位于起始分隔符的主诊断，并保留错误范围。不要因恢复制造能进入代码生成的伪造字面量。

## 5 Parser

### 5.1 分工

| 入口 | 负责内容 |
| --- | --- |
| `parse_file` | 首个 package、连续 import、顶层声明、EOF |
| `parse_decl` | 绑定、函数、结构体、枚举、trait、impl |
| `parse_type` | 具名/限定类型、泛型实参、函数类型、括号类型 |
| `parse_statement` | block、if、四种 for、switch、try/catch、defer、跳转、简单语句 |
| `parse_expression` | 一元、二元、调用、成员和中性方括号后缀 |
| `parse_pattern` | 字面量、负数字面量、绑定、通配符、限定枚举变体 |

运算符表直接来自 EBNF 的优先级定义。赋值仅由语句入口识别，不能出现在表达式树中。条件必须有花括号；解析器不接受隐式单句代码体或自动分号插入。

### 5.2 中性方括号后缀

parser 不查询符号表。对于 `f[T]`、`values[i]` 和 `tensor[i, j]`，构造 `NeutralBracketSuffix`；只有名称和类型阶段决定最终含义。

每项保存 token 范围以及表达式/类型候选。实现可以共享公共名字路径节点，或使用 token 范围的受控延迟解析。`func(i32) i32` 必须能作为类型候选保存，不能因为不是普通表达式而提前拒绝。

消解规则：

1. 基对象解析为可实例化的泛型声明时，按类型实参检查数量和约束。
2. 基对象为值时，按其索引能力检查。`Vec[T]` 只接受单项索引；多项索引必须由外部绑定明确支持。
3. `[:]` 类后缀固定为切片结构，不是泛型参数列表。
4. 泛型不接受整数常量实参；不能借 `f[3]` 引入常量泛型。
5. 仍有多个合法解释时报告歧义，不能依据“哪个后端更方便”选择。

禁止无界回溯。候选解析按 token 区间及解析模式记忆化，设置嵌套深度限制；超限时报错为资源限制，而不是把用户输入判成违反文法。

### 5.3 恢复

缺失 token 使用带位置的 `MissingToken`；错误表达式使用 `ErrorExpr`。同步点按上下文选择：语句的 `;`/`}`，声明起始关键字，switch 的 `case`/`default`。恢复时不能越过调用方负责的结束分隔符。

每轮解析要么消费 token，要么插入一次缺失 token 并返回上一层；不能反复在同一位置插入相同缺失 token。诊断数量达到配置上限后停止继续恢复，并给出单条“其余诊断已抑制”说明。第一版不要求边输入边复用单个 AST 节点，按文件重新解析是允许的。

## 6 模块、名字和作用域

### 6.1 模块解析

编译输入显式提供项目根、目标配置、标准库身份和依赖映射。`std` 指工具链标准库，`app` 指项目模块，其余首段通过项目清单解析。不得在系统目录、项目目录和网络中无序猜测同名包。

导入字符串在词法上是字符串，在名称阶段检查为合法逻辑路径：禁止绝对路径、反斜线、`..`、空段和非 ASCII 标识符段。省略别名时使用最后一段。依赖缺失或绑定不完整直接诊断；语义检查不自动安装依赖。

模块身份使用解析后的包身份与逻辑路径，不能仅使用短别名。同一份物理源码经不同别名重复加载时，解析层应将其归一为同一个模块身份。环境变量和系统安装位置必须先进入可复现配置；不能成为未记录的隐式搜索顺序。

### 6.2 声明收集和依赖

1. 解析所有参与文件，检查同一模块中 package 名一致。
2. 构造模块导入图并检查有向环；第一版包依赖必须无环。错误给出完整环路径以及相关 import 的源位置。
3. 对模块全部文件预收集顶层声明，建立符号身份，再解析签名和函数体。由此支持同一包内函数前向引用和相互递归。
4. 顶层值绑定仅允许 `const`。顶层 `let/var` 仍能被 parser 接受，但语义阶段报告未支持；不能偷偷生成动态初始化函数。
5. 常量依赖另外检测循环，不能把函数递归与常量循环混为一类。
6. 值类型布局递归交由类型布局验证器处理；仅由 import 图无环不能证明类型布局有限。

### 6.3 名字空间

- 普通名称采用单一词法名字空间，符号以 kind 区分变量、函数、类型、模块和类型参数。
- 同一作用域重复声明报错；嵌套局部允许遮蔽外层局部。先寻找最近的绑定，再验证其 kind，不跳过同名变量去寻找更外层类型。
- 内建名字位于最低优先级 prelude；`Self` 由 trait/impl 的类型环境提供，在其外不能被假定为特殊类型。
- 顶层声明包内共享；import 别名只在声明它的文件内有效。
- `_` 在绑定和模式中表示丢弃，不创建可读取符号。要求命名实体的位置不能以 `_` 建立可寻址实体。
- 默认包内可见，`pub` 明确导出。跨包读取私有声明报错；公开接口不得泄漏无法从外部引用的私有类型。`pub const` 按其最终公开类型图检查（不包含 callee 内部特化实参），即使该常量从未被使用。
- 模块成员、类型成员和实例成员分开查找；错误说明实际找到的符号 kind。

## 7 类型检查和推断

采用双向局部检查：已知声明类型和调用形参向表达式提供期望类型；表达式产生实际类型。不做全程序的任意隐式转换搜索。

### 7.1 最小推断规则

- 参数、字段和返回类型显式声明；省略返回类型为 `Unit`，不能从 `return` 反推函数签名。
- 未定类型整数字面量根据上下文确定类型；无上下文时 `i64`。浮点同理，默认 `f64`。范围、转换及运行语义见 `SEMANTICS.md`。
- 两个已经确定类型的数值变量不因“可以转换”而自动形成公共类型；需要显式转换。
- `[]` 需要元素类型上下文；非空列表在可检查的共同元素类型下成为 `Vec[T]`。
- 调用中通过实参和允许的期望类型约束泛型参数；无法唯一确定时要求显式类型实参。不得枚举程序中的所有类型来硬试。
- 泛型函数体在符号类型参数下检查；只可使用约束公开的能力。实例化阶段再验证实际类型及目标能力。
- 普通 `bool` 条件不接受整数或 Tensor 的隐式真假转换。
- 函数类型包含参数模式、返回类型和 `throws`，不包含参数标签。非捕获函数字面量先实现；捕获集非空时返回对应未支持诊断。

### 7.2 调用检查

每个调用先完成 callee 分类，再匹配形参。检查缺失参数、未知标签、重复提供同一形参、参数模式、泛型约束和外部可省略参数。普通源函数不支持重载、默认参数和可变参数。

函数值调用只能使用位置参数；直接解析到声明的函数、方法、构造器和有绑定的外部可调用对象可以使用命名参数。结构体构造要求所有字段各提供一次且使用命名参数。

**实参匹配顺序与求值顺序分开保存。** `f(second: a(), first: b())` 必须先求值 `a()` 再求值 `b()`，最后按形参位置传递临时结果；不能把表达式按标签排序后执行。若 `a()` 抛错，`b()` 不执行。调用对象及接收者也只求值一次。

### 7.3 Place 与模式

为可写位置单独建立 `Place` 分类。赋值目标只求值一次；复合赋值不能重新执行索引或成员基对象。第一版 `inout` 仅接受可写的平凡值整变量绑定（类型限制见 SEMANTICS），不接受引用容器、外部对象、字段、索引或带复杂别名的位置；独占、逃逸和 `move` 规则见 `SEMANTICS.md`。

模式先根据被匹配值类型检查，再创建分支作用域。裸标识符是新绑定，`_` 不绑定；枚举变体必须有类型限定。由被匹配值唯一确定的泛型实参可省略。检查 payload 数量和类型、重复 default、不可达分支和规范要求的穷尽性。

每个 case/default 即使没有额外花括号，也建立独立词法作用域。分支绑定不进入其他 case；分支正常结束执行该作用域的清理。trait 方法查找必须得到唯一适用的 impl；无法唯一确定时拒绝，不按文件或导入顺序任选实现。

## 8 控制流、错误和清理检查

检查上下文至少维护函数边界、词法块、循环/switch 目标、catch 作用域、defer 边界和 unsafe 深度。

- 非 `Unit` 函数的所有正常出口必须返回值。`throw` 是错误出口；无限循环是否具有正常出口由保守控制流分析决定。
- `break` 指向最近循环或 switch；`continue` 指向最近循环。进入/退出普通块不会创建新的函数返回边界。
- 表达式效果记录可能传播的错误类型集合。源函数签名最多声明一个错误类型；多个局部错误类型必须先被捕获或显式转换，不能自动变成隐式联合类型。
- 本语言错误按类型匹配；外部错误子类型匹配仅使用绑定声明的关系。
- try 体的错误进入对应 catch。catch 自身产生的错误交给外层处理，不能被同一个 try 的其他 catch 捕获。
- 构造 `Result.Err` 不产生错误效果，也不自动展开。
- defer 体不得向外传播未处理错误，也不得通过 return/break/continue 越过 defer 边界。defer 内自己的循环可以正常 break/continue。
- defer 在其所属词法块退出时后进先出执行；返回表达式在清理前求值。捕获读取、移动冲突和隐式销毁顺序按 `SEMANTICS.md` 校验。
- defer 仅在控制流实际到达声明时注册；每次进入作用域使用独立注册状态。不能执行未到达的 defer，不能把上一轮循环的注册带入下一轮。
- unsafe 只影响明确声明的受限操作许可，不关闭名称、类型、错误、所有权或目标能力检查。

检查结果保存到 HIR 和控制流事实中；后端只能使用这些结果，不能重新推导另一套 catch 或 defer 规则。

## 9 诊断契约

稳定的字符串 `code` 用于工具判断；用户可读文本可以改进或本地化。机器输出采用 `contracts/diagnostic.schema.json`，内部 SourceSpan 的 begin_byte 在序列化时转换为 start_byte。输出格式示例如下，偏移值仅作示意：

```json
{
  "schema_version": 1,
  "compiler_version": "example-not-built",
  "source_revision": "content-hash",
  "status": "error",
  "diagnostics": [
    {
      "phase": "type",
      "severity": "error",
      "code": "E_TYPE_MISMATCH",
      "message": "实参类型为 string，参数 value 要求 i32",
      "primary": {"path": "main.wz", "start_byte": 48, "end_byte": 53},
      "related": [],
      "notes": [],
      "fixits": []
    }
  ]
}
```

诊断至少区分：编码/词法、语法、模块/名称、类型、效果/所有权、目标能力、编译器内部错误。内部断言失败不能包装成用户语法错误。超时、取消或触发内存/递归上限，也不能报成源码不合法。

建议注册的代码包括 `E_PARSE_EXPECTED_TOKEN`、`E_IMPORT_CYCLE`、`E_NAME_NOT_FOUND`、`E_TYPE_MISMATCH`、`E_CALL_ARGUMENT`、`E_EFFECT_UNHANDLED`、`E_CLEANUP_ESCAPE`、`E_CAPABILITY_UNAVAILABLE`。禁止根据英文 message 字符串判断诊断类别。

同一个根错误引发的派生诊断要抑制，比如未知变量得到 `ErrorType` 后，不再在每个父表达式上重复报类型不匹配。JSON 输出不得混入日志；日志使用 stderr 或独立事件通道。

## 10 增量检查和 LSP

第一版缓存粒度为文件和模块，不承诺字符级增量重建。缓存键至少包含源码内容、编译器/规范版本、目标配置、功能配置、依赖锁定信息、外部绑定版本，以及被使用的模块接口摘要。

模块接口摘要覆盖公开签名、泛型声明及需要跨模块实例化的函数体、影响外部常量求值的常量值。只哈希函数名字和返回类型会造成错误缓存命中。

查询必须可取消；旧版本完成后不得覆盖新版本诊断。导入补全读取模块索引，不能执行模块。补全、跳转、悬停使用解析结果中的 SymbolId 和 SourceSpan，不从格式化后的诊断文字反推。

公用 arena 的读写要有明确边界：解析/检查阶段在查询私有上下文中构建，发布后只读。并发查询不能修改另一个查询的符号或类型表。

## 11 验收用例

| 编号 | 输入或动作 | 必须观察到的结果 |
| --- | --- | --- |
| FE01 | 运行基线 59 项自测和 7 个正例 | 词法/语法分类与基线一致；不能把它记为类型检查通过 |
| FE02 | 同一源码分别保存 LF、CRLF、起始 BOM | 程序字面量值一致，原始源区间分别正确 |
| FE03 | 中文字符串后出现类型错误 | CLI 与 LSP 均标出同一源码片段，不能按字节误算 UTF-16 列 |
| FE04 | `007`、`0x_FF`、非法 Unicode 转义 | 词法拒绝，定位正确，无无限恢复 |
| FE05 | 一条语句缺少分号，下一条还含另一个错误 | 报出有限且相关的诊断，后续声明仍可用于 IDE |
| FE06 | `f[T](x)`、`callbacks[i](x)`、函数类型实参 | parser 保留候选；语义阶段作正确分类 |
| FE07 | 命名参数调换顺序且各有可观察副作用 | HIR 求值计划保持源码顺序；不得按形参顺序重新执行 |
| FE08 | 同包两个函数相互递归；两个包相互 import | 前者允许，后者给出包含两条 import 位置的环诊断 |
| FE09 | `let a i32 = 1; let b i64 = a;` | 无显式转换时类型拒绝 |
| FE10 | 不声明 throws 的函数直接调用 throws 函数 | 效果拒绝；相同源码在语法模式下允许 |
| FE11 | catch 中再次抛出相同类型 | 交给外层处理，不进入同 try 的后续 catch |
| FE12 | defer 内 return；defer 内自己的 for/break | 前者拒绝；后者不因存在 break 就一概拒绝 |
| FE13 | 未登记的 `np.some_missing_api()` | 报接口未覆盖/名称缺失，不降成动态 Any |
| FE14 | 顶层 `var`、捕获闭包、复杂 inout 位置 | 明确未支持诊断，不绕过语义生成代码 |
| FE15 | 更改依赖公开常量或泛型函数体再检查调用方 | 相应缓存失效 |

每条正例必须按“能解析、能通过语义、目标支持、实际执行”分别记录。只有对应阶段实现并完成验证后，才将其标为通过。

## 12 完成条件

交付前端库、公开接口头文件、诊断注册表、单元/集成用例、CLI 的检查入口和阶段产物打印。使用链接依赖检查确认公共前端没有 LLVM/CPython 依赖。AST/HIR 打印不得包含指针地址等运行间不稳定内容；同一输入及配置应产生相同的可比较输出。
