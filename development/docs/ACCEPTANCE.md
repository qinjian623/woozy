# 验收与测试规范

本文件定义以后实现编译器时需要提供的证据。这里的期望结果和阈值是验收条件，不是已执行结果。当前实测只包括随附语法原型的检查、Python 对照文件的语法编译和 NumPy 数据准备；原生编译器、转译器和 PyTorch 训练尚无执行结果。

## 1 结果分类

每条测试至少记录测试 ID、输入版本、目标/后端、命令、预期、实际结果与环境。状态使用以下五种之一：

| 状态 | 含义 | 是否计入通过 |
| --- | --- | --- |
| passed | 已执行，观察到规定的结果 | 是 |
| failed | 已执行，结果与规定不符 | 否 |
| skipped | 本次矩阵明确排除，写明原因 | 否 |
| not_run | 应运行但缺少依赖、设备或时间 | 否 |
| unsupported | 对该后端明确不提供的能力，已验证编译期诊断 | 只计入“不支持诊断”用例，不计入功能运行通过 |

缺少真实 PyTorch 时，NumPy/PyTorch 集成必须是 `not_run`。允许开发者运行不依赖它的前端测试，但 T10 不能标为完成。针对尚未支持的能力，既不能崩溃，也不能静默改用不同语义。

## 3 分阶段用例

### A01 源码位置与诊断

- LF 与 CRLF 的等价程序具有相同词法意义；报告仍指向原文件的正确字节区间。
- 带 BOM 的首个 token、中文字符串、非 BMP 字符、制表符后的错误位置正确。
- UTF-8 字节位置转换到 LSP UTF-16 位置后，可准确选择原错误文本。
- 文件错误、取消、编译器内部异常和用户代码诊断分开报告。
- 诊断 JSON 可稳定解析；测试断言错误码和位置，不硬编码整段自然语言。

### A02 词法、解析与恢复

- 迁移全部 59 项边界用例，保持分类。允许改进错误码，但需要提供明确映射。
- 七个正例能够形成完整 AST；五个词法/语法负例拒绝；四个语义负例形成 AST。
- 缺少分号、括号或块结束后，后续独立函数仍可被发现；不产生无限恢复循环。
- 注释、字符串、数字、泛型/索引候选的跨度覆盖正确源文本。
- 显式函数类型实参和返回函数类型的 `throws` 归属有独立用例。
- 出现语法错误时，不能把带错误节点的模块当作成功结果提交给后端。

### A03 模块与类型

- 不存在的模块、不可见导出、同名导入、错误依赖映射和模块依赖环得到明确诊断；顶层动态初始化不得被隐式接受。
- 项目模块不能通过偶然目录顺序覆盖 `std` 模块。
- 仅依赖纯声明绑定时，即使 Python 包未安装，静态检查仍可完成。
- `let n = 1;` 按规范推断；显式类型的边界值、越界字面量、负最小值分别检查。
- 字符串赋给 `i32`、给 `let` 重新赋值、读取 `_`、遗漏非 Unit 返回均拒绝。
- 已有 `Result[T,E]` 不会自动变成 `T`。
- 命名实参先按源码顺序求值，再绑定到形参；包含副作用和中途抛错的用例能观察到差异。
- 泛型约束、实例化缓存、递归实例化限制、trait 方法目标与 enum 模式绑定有独立用例。

### A04 原生执行与 LLVM

- 同一程序在 O0、O2 下产生一致的返回值、输出、错误路径与可观察副作用。
- 自有 IR verifier 和 LLVM verifier 都通过；人为构造的无终结块、类型不匹配、错误拥有路径分别由对应层拒绝。
- 目标 triple、CPU 特性和 DataLayout 来自任务配置；交叉编译不继承宿主指针大小。
- 标量参数/返回、简单聚合类型、嵌套调用和跨模块调用都实际链接执行。
- 固定宽度整数加减乘和取负按规范回绕；整数除法向零截断，最小负数除以 -1 按规定特判；除零、移位和转换边界按 `SEMANTICS.md` 检查。运行时 Panic 不得被 typed catch 意外捕获；不能以宿主语言行为作为答案。
- 浮点测试使用规定的 NaN、无穷、带符号零和舍入规则；普通构建不得偷偷启用改变语义的 fast-math。
- 用例必须运行产物。只生成 `.ll`、只通过 verifier 或只生成对象文件分别记录，不能记为原生运行通过。

### A05 Python 与原生公共子集

为每项差分测试记录程序文本、输入、期望类型和可观察事件序列。两个后端分别编译，比较输出与事件，不比较生成代码文本。

| 测试内容 | 比较方式 |
| --- | --- |
| 整数和布尔运算 | 按语言固定宽度与失败规则精确比较 |
| 浮点运算 | 无运算顺序差异时优先精确比较；其他容差必须由具体测试明确给定 |
| 调用与命名参数 | 比较求值事件、次数与顺序 |
| 分支、短路、循环 | 比较进入/退出次数与副作用 |
| 返回与错误传播 | 比较结果分支、错误类型及有效 payload |
| defer | 比较清理事件列表和返回值，不仅比较最终退出码 |
| 模式匹配 | 比较命中分支和绑定值 |

Python 的大整数、除法、异常类型和垃圾回收行为不能直接作为本语言标准。差分只覆盖明确的公共子集；native-only 功能要单独验证 Python 后端的拒绝诊断。

### A06 错误、清理与函数值

至少覆盖以下路径：

1. 正常退出块，执行该块已注册的 defer，顺序为逆注册顺序。
2. 返回值表达式先计算，随后执行离开的各层清理，再返回已计算的值。
3. `break`/`continue` 只清理其实际离开的作用域；循环每轮块退出都正确执行。
4. 被调用函数抛错，未求值的后续实参或语句不会执行，已进入作用域的清理执行一次。
5. 错误传播进入外层 catch 前，内层清理完成；catch 不回滚已发生的副作用。
6. defer 内可以局部捕获错误，但未处理错误不得逃出清理体。
7. 普通返回值为 `Result.Err` 时，不触发 throws 传播。
8. 声明可能抛错的函数值不能赋给不抛错函数类型；调用同样需要处理效果。
9. 返回一个可能抛错的函数，不使外层构造函数自动变成 throws；括号规则与类型规则同时满足。

测试应记录一个清理事件数组，如进入块、求返回值、清理内层、清理外层、捕获错误。不要只看程序未崩溃。

### A07 所有权和 ARC

具体合法性由 `SEMANTICS.md` 决定；测试至少包括：

- 移动后读取、重复移动、借用逃逸、重叠 `inout`、在受限借用期间销毁或移动拥有者。
- 分支一侧移动、另一侧保留时，合流后的有效状态。
- 包含引用字段的结构体、枚举有效 payload、Vec 元素和部分构造对象的销毁。
- 成功、错误、提前返回与容器构造失败时，分配对象均按规则释放。
- 借用参数不会无故转移所有权；返回拥有值不出现重复释放；`move` 按规定消耗整个拥有绑定，`inout` 不得逃逸。
- Vec 共享引用应观察到规范规定的共享修改；不能偷偷引入写时复制，制造与另一个后端不同的对象身份。
- 没有未声明的跨线程共享；实现线程共享前不能用单线程测试推导并发安全。
- 外部 Python/C++ 对象遵循各自绑定的 ownership 契约，不能混用释放器。

通过条件是对象生命周期与可观察析构正确，且没有释放后使用和非预期存活对象。允许优化消除冗余 retain/release，不能要求 O0 与 O2 的内部调用次数相同。需要时用测试运行库、地址检查器及失败注入验证；仅靠静态 IR 快照不能证明生命周期正确。

### A08 NumPy 与 PyTorch 真实集成

在锁定的 Python、NumPy 和 PyTorch 环境中，编译并执行 `04_numpy_torch.wz` 的 Python 产物。同时执行手写参考，记录全部依赖版本和 CPU 平台。

首批验收条件：

- NumPy 的 x、y 形状为 `(128, 1)`，dtype 为 `float32`，`y = 2x + 1` 成立。
- 数据转换显式使用 `torch.tensor`；没有生成未声明的列表转换或隐式设备切换。
- 使用 CPU 的 `nn.Linear(1,1)`、MSE 和 SGD，学习率 0.1，运行 200 次优化器更新。
- 训练返回真实的零维 `torch.Tensor`；`requires_grad` 与 `grad_fn` 符合本例的 autograd 路径。
- 转译产物不插入 `detach`、`item`、`cpu` 或 `numpy`。测试读取数值时可以显式使用它们，并与被测源码区分。
- 在测试夹具中为 Module 注册调用 hook，观察 `model(x)` 的调用语义仍生效；不能只比较损失数值。
- 测试夹具计数应观察到 200 次 backward、200 次 optimizer.step；不得将训练循环省略成参考结果。
- 损失有限且非负；本例最终 MSE 预设验收阈值为 `< 1e-3`。这是待实测的功能阈值，不是已得到的性能或精度结果。
- 生成版本与手写参考的最终损失使用明确容差比较，初始设为 `rtol=1e-5, atol=1e-6`；若因依赖版本需要修改，保留复现证据并同步锁定和测试说明。

还需独立的小例验证 ndarray/Tensor 透传的身份、原地修改的可观察效果、调用参数顺序和抛出 Python 异常时的桥接行为。绑定函数传回对象时，没有要求复制的地方不能暗中复制。

真实训练通过后仍不能声称支持 GPU、AMP、分布式、动态 Python 反射或任意 PyTorch API。每项能力独立记录。

### A09 C++、系统接口与多平台

- C++ 包装测试覆盖创建、借用、销毁、返回错误和抛 C++ 异常；异常必须在受控边界转换。
- 同一个 handle 不被错误的 runtime 销毁；借用返回值不被当作新拥有值重复释放。
- `std/os` 测试覆盖成功 I/O、部分操作、错误返回和句柄清理。阻塞、缓冲和返回值不能仅根据名称推定。
- Linux、Windows、macOS 分别记录实际测试状态。只在某平台生成对象文件，不能声称在该平台运行通过。
- 交叉编译记录编译宿主、目标、SDK 与链接器；缺失 SDK 属于工具链问题，不能伪装成源码错误。
- 平台不支持的 raw syscall 或库能力在检查/构建阶段明确拒绝，不静默替换成行为不同的路径。

## 5 性能与稳定性

快速检查的性能分别记录冷启动和进程内增量检查，注明文件大小、模块数、机器、构建模式和采样次数。先建立基线，再设回归阈值；当前不脱离环境承诺具体的毫秒数值。

优先检测真正风险：错误恢复是否卡死、超深嵌套是否受控失败、实例化是否无限扩张、源文件变更是否错误复用缓存。针对 parser 和 IR verifier 适量做生成输入与扰动测试；发现问题后把最小复现收进回归集。

运行性能必须与同等语义、相同输入、相同硬件的参考实现比较。单个数值内核快不能推导所有 ARC 程序快；编译耗时和运行耗时分别报告。不要以新增大量重复测试替代修复已发现的风险。

## 14 本轮补齐的边界用例

- Panic 从普通代码或 defer 内发生时，typed catch 不捕获，后续语言 defer 不执行；检查 Python finally 的退出原因隔离。
- 同一个 owned 外部句柄复制后只有最后一个拥有者调用一次外部销毁，拒绝没有共享包装或 retain/release 协议的类型。
- 临时值按 full-expression 逆创建顺序销毁；后续实参抛错时，先前 move 实参的临时所有权被销毁，源绑定不恢复。
- for 初始化、for-in 每轮绑定、case/default、catch、函数参数与函数体作用域符合 SEMANTICS 的作用域表。
- 活跃 Vec 迭代中的结构修改在发生前 Panic；覆盖修改后立即 break/return 和删除后恢复长度。
- inout 只允许首版平凡值整体绑定；拒绝共享 Vec 或外部对象的 inout，不把槽独占推导成深层 noalias。
- Python typed error 使用稳定逻辑类型身份；分别生成并缓存多个模块后，类型匹配仍正确。
