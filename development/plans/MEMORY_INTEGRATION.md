# 循环回收接入顺序

这是待实现的接入要求。独立 GC、Weak 和线程暂停测试通过，仍不能证明真实 Woozy 程序已经自动回收循环。

## 对象与根

- 对可能形成环的拥有对象登记 trace、clear、retain、release、invalidate_weak 操作。引用计数减去图内强边后的正数作为外部根；重复边必须逐条计数。
- Vec、struct/enum 中的拥有成员及闭包环境都参与遍历。Weak 不算强边。Python/C 对象自身的内部环由宿主管理，不能当作可遍历的 Woozy 对象。
- 正在执行的线程持有自己的上下文，视为外部根。线程返回后按既有规则清理上下文；最后一个用户 Thread 句柄被清理，不代表线程已经结束。
- 普通最后强引用释放时，先从登记表移除对象，再清理内容，避免回收器读取清理了一半的对象。
- Vec 只遍历已经初始化的前缀。分配时 length 可以已设定而 initialized 仍为零；分配阈值只能提出请求，不能在构造一半时开始遍历。

## 修改对象与暂停线程

- 函数入口和循环头检查原子请求位。没有请求时不调用 gettid，也不查登记表。显式 continue 必须经过下一次检查。
- 拥有值的写入、move、drop 是不可在中途暂停的操作。必须支持嵌套的修改区间，退出最外层后才处理回收请求；进入 SAFE 也不能把未完成的对象修改当作稳定状态。
- 同样覆盖编译器直接发出的引用计数、memcpy、初始化进度和字段写入；只包运行库入口会漏掉这些内联操作。
- Vec 替换、clear、缩短长度，先移走旧边并公布新状态，再释放旧值。释放外部对象可能重入 Woozy，不能让重入代码看到失效成员。
- struct/enum 字段替换也先将旧值移入临时拥有槽、发布新字段，再释放旧槽。禁止暂停不能阻止同线程外部析构回调读取对象。
- 可能阻塞的系统调用、锁等待和外部调用，在图写入完成后进入 SAFE，返回后先离开 SAFE 再访问图。外部线程通过回调进入 Woozy 时登记；只注销本次实际新建的登记。
- 不得暂停仍持有分配器、环境、创建进程等运行库锁的线程，再让回收器获取同一把锁。此类锁操作要与修改区间、SAFE 和 fork 顺序一并接入。
- stop 超时须完整撤回请求并恢复线程，保持对象不变。超时不能作为已经完成回收的记录。

## 清理与 Weak

停住其他修改线程后，顺序固定为：保留全部白对象、使全部白对象的 Weak 失效、清理全部白对象、释放临时保留。第一个 clear 开始前，任何白对象都不能再通过 Weak upgrade 成功。

失效后的 canonical Weak slot 必须保持关闭；clear 或外部清理回调不能重新安装可升级的控制块。地址重用时由新对象构造重新置空。

纯 Woozy 图中的外部资源释放可能调用 Woozy、创建线程或等待线程。回收时先移走这些资源，将其释放推迟到恢复线程以后；不能在其他线程全部暂停时执行任意外部析构回调。Python 后端也应把旧 Python 容器或宿主引用保留到本次图修改结束，防止宿主析构重入。

待释放队列持有资源的强引用，直到实际 drop 完成。先恢复线程并结束本轮 collecting 状态，再执行外部析构；析构可以再次触发 GC，旧队列及正在释放的资源仍须有效。

## fork 与已有程序

fork 的运行库锁与回收器先后顺序要有真实多线程测试。子进程只保留调用线程登记、更新 tid、重置运行库自己的锁；不伪造消失线程的 ARC 清理，不重置业务锁。hosted 的直接 libc fork 与 std/process.fork 均须遵守同一规则。

已有 hosted prepare 顺序为 launch、environment、allocator。fork 应在取得 launch 锁前进入修改区间，不能持有这些锁等待其他线程暂停。接入 Weak/GC hooks 时须列出完整顺序，覆盖父进程逆序释放、失败恢复和子进程重置。

线程上下文若只作为未登记的外部强引用，可继续视为根；若将 ThreadState 加入遍历，必须另有 context_live 状态：复制完成后才可遍历，返回或启动失败时先撤下可见上下文再 drop，不能因保留已完成 Thread 句柄而读取旧上下文字节。

没有可形成环类型的程序不应无条件登记每个基本数值 Vec。自动触发阈值随存活图增长，避免对不断增长的对象图每固定少量分配就全图扫描。需要测量加入检查后的排序和基本程序耗时。

## 接入后的检查

- 真实 Wz 程序中的自环、双环、重复边、带活根的环、死环指向活对象、嵌套 struct/enum，以及闭包环境环。
- 不主动调用 collect 的持续分配程序，证明内存或登记对象数保持有限；只有手动 collect 测试不能证明自动触发。
- return、typed throw、defer、continue、线程退出、外部回调重入，以及 fork/exec。对照准确 drop 次数，检查 Weak 在第一次 clear 前已全部失效。
- Native O0/O2、Python，线程竞争与 sanitizer，默认程序仍无 libc/libstdc++ 依赖；未接入的后端明确保持未完成。

源码级 Weak 可接受哪些类型尚待确定。struct/enum 是按值复制，string 没有已声明的对象身份，不能因为底层恰好有指针就擅自开放 Weak。捕获绑定和 move 捕获语法也继续等待用户答复。
