# Linux Native 运行库的 Wz 迁移

本轮面向 Linux x86_64。优先把只依赖输入值的算法移到 Wz。已发布的 Native ABI 继续可用，种子编译器、自举编译器和生成程序使用的运行库分别核对。词频实验验证了顺序读取 UTF-8 的效果，原示例保留。本仓库处理同类库函数。

## 已确认的字符串耗时

C++ 种子和 Wz 自举编译器都把字符串下标和切片交给 `lang_text_at_v1`、`lang_text_slice_v1`。它们从开头解码到所需码点。按下标遍历长度为 n 的字符串要反复扫描前缀，最坏耗时 O(n²)。连续拼接不断增长的输出也会重复复制前缀。 [种子代码生成](../../src/backend/native/emit.cpp) · [自举代码生成](../../selfhost/src/wzcc/nativeemit/c_instructions.wz) · [字符串运行库](../../runtime/native/text.cpp)

优先改动查找、拆分、空白扫描、替换、拼接、ASCII 大小写和字素簇拆分。结果仍按 Unicode 码点编号。内部用字节游标向前推进，必要时收集字节区间并一次生成输出。日期解析先拒绝超过 RFC 3339 语法长度的输入。HTTP 输出中的重复索引在流式服务器改动合并时检查。

## 哪些代码放在哪里

| 部分 | 迁移内容和保留内容 |
| --- | --- |
| 字符串 | 查找、切分和批量转换放在 Wz。保留字符串布局、分配和引用计数入口。用真实目标文件验证 UTF-8 验证内核能否从 Wz 调用、由旧 ABI 转接，以及生成目标文件需要哪些运行库符号。 |
| 数字 | 整数十进制读写先移到 `std/strconv`。已有整数 C 符号继续服务旧目标文件。浮点算法迁移前需保证舍入、负零、上下溢和最短表示与现有实现一致。 |
| IP 地址 | IPv4 和 IPv6 文本转换移到 `std/net`，保持严格解析和现有规范输出。套接字系统调用、地址结构和 C 符号保留。 |
| 文件和网络协议 | Wz 实现文件操作组合、请求解析、缓冲、重试和超时。Linux 系统调用、内核结构转换和 ABI 参数传递留在底层。 |
| 进程启动与内存 | 保留 ELF 启动、线程和系统同步、分配器、引用计数与 GC 所需入口。若 Wz 目标文件离开这些入口无法运行，记录实际未定义符号和依赖原因。 |

用发布版 Wz 编译器生成了 UTF-8 校验和计数函数的 Linux O2 目标文件。实验给符号临时改名后，由 C 调用，并和现有 C++ 字符串运行库逐例比较。5,048 项通过。生成的目标文件仍引用 `lang_gc_runtime_poll_v1` 和 `lang_native_panic_v1`。运行库构建还未接入这个对象，接入时需要核对 GC 调用和编译器生成的符号。

标准库中的字符串查找、拆分、替换、ASCII 大小写和字素切分已改为顺序处理。需要完整扫描的接口仍可能复制输入字节。`parse_rfc3339` 在扫描前拒绝超过 35 个码点的输入。

字符串哈希对不超过 32 字节的键保留原有循环，更长的键顺序解码一次。C++ 种子和 Wz 编译器生成的 O0、O2 程序对 105 个键给出相同的哈希值。用 Wz O2 编译的词频程序处理 512 字节的词，ASCII 用例 CPU 时间中位数由 1761 ms 降到 362 ms，UTF-8 用例由 1356 ms 降到 276 ms。4 MiB 短词用例用时基本相同。

整数解析和格式化的 Wz 原型与原生实现对照，O0、O2 的输出摘要完全相同。原型在 O2 仍慢约 2–4 倍，公开接口继续使用原运行库。之后用 Wz 直接读字节指针，并把十进制格式写到调用者提供的缓冲区。与 C++ 运行库在同一进程比较，528,036 项通过。该原型仍带 GC 轮询和临时符号改名，未接入发布构建。

IPv4 和 IPv6 文本转换的 Wz 原型在 O0、O2 对照中均得到相同的 24,069 行输出。优化后 O2 的解析仍约慢 2–2.4 倍，格式化约慢 3.7–4.1 倍。当前公开接口继续调用原运行库。原型里每次调用的字节复制、向量分配和单字节检查是主要成本，迁移需再比较直接操作小缓冲区的实现。

## 如何验证

每批分别跑 Linux Native O0 和 O2，检查有效与非法输入、错误类型、边界、资源释放。通过 LLVM IR 或目标文件确认新程序实际调用哪份实现。对旧目标文件回归检查既有 C 符号，检查 ELF 的解释器和动态依赖。性能测量用同一编译器、输入和运行环境，保留基准和候选实现的大小、时间及退出码。

把最终使用的种子、运行库和标准库固定到实际解析出的路径与摘要。由种子编译 Wz 编译器，再用新编译器重编译，并运行迁移用例。进入构建的实际运行库和标准库都需要核对，普通程序通过测试只能说明该批程序的表现。 [自举入口](../../selfhost/Makefile) · [运行库构建](../../src/backend/native/CMakeLists.txt)
