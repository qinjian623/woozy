# 长任务执行与结束通知

长编译和整套测试由已登记父会话的 Bridge operator 在前台执行，沿用现有完成事件，不另建通知服务或定时器。

## 执行

- 派单时写清操作 ID、固定输入、命令、原始预算和完成条件；启动前先确认同一操作是否已在运行，避免重复执行。
- operator 必须等命令真正结束后再交付，不用独立后台进程或 `launch-once.py` 的 detached 入口代替前台等待。
- 沿用已有 bounded process 封装。先保存 stdout/stderr 原始字节和四个过程字段，再做 JSON 解析和断言。bytes 必须先编码，不能因附加元数据序列化失败而丢掉退出码。
- 每条命令保存真实 PID、argv、预算及原始 exec 记录；若能在执行期间读取进程开始时间，一并记录。短命进程采不到的字段留空，不事后倒填。
- 输入的前后快照各自重新读文件计算哈希，不能共用哈希缓存。如果发现旧记录复用了缓存，保留旧报告，独立重算当前文件并写明检查时间；不要为了补记录重新执行测试。
- 读取冻结目录的所有 Python 命令都加 `-B`，并在导入项目模块前设置 `sys.dont_write_bytecode=True`；子进程环境设置 `PYTHONDONTWRITEBYTECODE=1`。普通导入会生成缓存导致输入核对失败，不得通过忽略缓存放宽检查。
- runner 已对编译器调用 `strace` 时，外层不能再套 `strace`；外层保留 PID、预算、原始输出和清理记录，编译器的 exec 记录取自内层日志。目标程序没有 exec 日志时单列限制，不能写成所有命令均已核对。
- 准备阶段与实际启动共用输入读取函数；改动 `main` / `SystemExit` 后检查所有 `runpy` 调用。启动控制只在临时目录替换最终 exec，确认唯一 claim 能到达 controller；报告控制使用实际调用语句和两角色记录形状。
- 每代编译预算仍为 21600 秒。三代编译加准备时间可单独设置 Bridge 的 `requirements.task_timeout=86400`（先确认新 worker 支持 `task_timeout_v1`）；这不延长单条编译或测试命令的预算。
- Bridge 总时限到期只说明操作被中断，不能据此改写已保存的编译器或用例结果。所有失败和未运行项保留。
- 原始资料放进项目 `checks/` 下的新目录，worker 工作树只留小报告，避免结果采集时枚举大量生成文件。

## 结束与通知

1. operator 在首行写明实际结果（成功、失败或中断），以及 exit/timed_out 和原始记录位置。预期失败的测试要单独标明。
2. Broker 产生完成事件后，分别核对入队 `enqueued` 与原生接收 `received`。会话忙碌时消息可能排队；不承诺立即送达。
3. Root 读取 `agent_result`，核对实际文件和测试后再执行 `agent_review`，随后按准确事件号发送 `parent_ack`，不把 ACK 当成此前已送达的证明。
4. 关闭不再使用的会话，并确认所属进程停止。暂停期间不启动依赖任务或自动重跑失败任务。
