# 长任务执行与结束通知

长编译和整套测试由已登记父会话的 Bridge operator 前台执行。使用现有完成事件，不另建通知服务或定时器。

## 执行

- 派单写清操作 ID、固定输入、命令、原始预算和完成条件。先查同一操作是否已经运行，避免重复执行。
- operator 等待命令真正结束后再交付；不用独立后台进程或 `launch-once.py` 的 detached 入口代替前台等待。
- 沿用已有 bounded process 封装。先保存 stdout/stderr 原始字节和四个过程字段，再做 JSON 解析和断言。bytes 必须先编码，不能因附加元数据序列化失败而丢掉退出码。
- 每代编译仍为21600秒。三代加准备时间可单独设置 Bridge `requirements.task_timeout=86400`；先确认新 worker 支持 `task_timeout_v1`。这不是延长每条编译或测试命令的预算。
- Bridge 总时限到期只说明操作被中断，不能据此改写已保存的编译器或用例结果。所有失败和未运行项保留。
- 原始资料放项目 `checks/` 的新目录，worker 工作树只放小报告，防止结果采集枚举大量生成文件。

## 结束与通知

1. operator 首行写实际结果：成功、失败或中断，以及 exit/timed_out 和原始记录位置。预期失败的测试要单独标明。
2. Broker 产生完成事件后，分别核对入队 `enqueued` 与原生接收 `received`。会话忙碌时消息可能排队；不承诺立即送达。
3. Root 读取 `agent_result`，核对实际文件和测试，再 `agent_review`。随后按准确事件号 `parent_ack`，不把 ACK 当成先前已经送达的证明。
4. 关闭不再使用的会话，并确认所属进程停止。暂停期间不启动依赖任务或自动重跑失败任务。
